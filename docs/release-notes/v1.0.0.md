**The first release under semantic versioning.** The public API — everything in
`log_foundry.__all__`, the `Sink` protocol, and every shipped sink class — is frozen for the whole
of `1.x`: nothing is removed or renamed, and no signature changes in a way that breaks a caller
until `2.0.0`. Behaviour is not frozen by that promise; a defect is still a defect, and fixing one
can change what a broken path does.

`1.0.0` is not a feature release. It is a reliability release. Three audit arcs — SPEC-024..033,
SPEC-034..047 and SPEC-048..050 — worked through the paths where the library could lose an event,
fail its caller, block forever, or report health it could not back up, and SPEC-051 through
SPEC-055 closed out what those arcs left open before the tag. Each item below was **reproduced by
running it** before it was fixed. That is a description of the work done, not a claim that no such
path remains: the failure modes are the part that has been audited hardest, and the ones still
open are tracked in `docs/architecture.md` §12.

**Signatures changed very little; behaviour changed a lot.** Read *Upgrading from `0.10.x`*
below before you bump — several of the changes are silent.

## What the arcs fixed

- **An HTTP redirect lost the batch and forwarded your credentials.** `urlopen`'s default opener
  follows a 301/302/303 on a POST by rewriting it as a body-less GET and **keeping every header**.
  So an `http://` collector behind a load balancer that redirects to `https://` lost every batch it
  was ever sent, sent the `Authorization` header to a host you never configured, and read the
  redirect target's `200` as a successful delivery — every counter clean. It reached every
  HTTP-family sink and Sentry's HTTP fallback. A 3xx is now refused, counted and announced.
  **If you ship to an HTTP endpoint over a redirecting hop, treat any bearer token in that
  configuration as disclosed to the redirect target and rotate it.**
- **The AWS batch sinks duplicated events on a partial failure.** `SQSSink`, `SNSSink`,
  `KinesisSink` and `FirehoseSink` called their client unguarded inside a chunk loop, so a fault on
  chunk N escaped `emit` after chunks 1..N-1 had landed and the worker's retry re-sent the whole
  batch. The exit drain is one large batch by construction, so it is exactly this shape. A client
  exception now costs its own chunk and nothing else.
- **Per-request context leaked between requests.** Baggage and an adopted trace context were
  written into `contextvars` and never taken back out, so on a thread serving requests
  sequentially one request's `user_id` reached the next request's events, and a warm container
  kept joining a trace whose process had exited. Both are released when the root span closes —
  baggage *restored*, an adopted context *cleared*, because an inbound context is a one-shot
  handoff rather than a process default.
- **`flush()` did not reach an open span, and the README's own serverless recipe was the case
  that broke.** Calling `flush()` inside a `@trace` function delivered **zero of two** events with
  every counter clean. A flush now sweeps open spans and hands their buffers to the worker.
- **Sinks that lost everything reported success.** A dead syslog socket produced a truthy
  `flush()` and an all-zero `health()` while every message was lost. A sink that can prove it
  delivered nothing now raises, so the retry engages and the loss is counted. Three cases stay
  quiet deliberately — an unadjudicable batch response, a rejected SQS sender fault, and an
  oversized event — because a retry there duplicates rather than recovers.
- **A sink's backoff paused all delivery, including through `shutdown()`.** `HTTPSink` passed a
  server-supplied `Retry-After` straight to `time.sleep`; measured, `Retry-After: 8` at the
  default `max_retries=3` blocked `shutdown()` for 22.01 s, and `86400` would have stalled
  logging for a day. Every retry backoff is now bounded, clamped, and cut short by a shutdown —
  while only ever shortening a *wait*, never skipping *work*. Read that as scoped to backoff
  rather than to every wait: `Sink.close()` takes no timeout and is still unbounded on both
  delivery paths, which `docs/architecture.md` §13 *Known constraints* records as accepted. The
  case that is simply still open — `NATSSink`'s exit drain — is in §12 *Open items*, which names
  what would close it. Its connect loop is no longer one of them:
  `NATSSink(max_reconnect_attempts=0)` used to block the constructor indefinitely and now raises
  `ValueError` before it connects at all.
- **The exit drain overwhelmed the whole HTTP family.** `Worker._final_drain` hands a sink the
  entire exit backlog — 5,980 events, measured — and no sink in that family chunked it: five
  overrode `emit` and the sixth inherited a base `emit` that sent the batch in one request the
  destination rejected whole. `HTTPSink` is now a template method that owns the chunk loop, and
  subclasses extend it through `_render` / `_body` / `_handle_response` instead.
- **Concurrent emitters could corrupt a sink.** A level call with no active span emits on your
  thread, against the same sink object the worker is draining into. Unlocked, `SQLiteSink` did not
  merely lose rows — it killed the interpreter with a bus error.
- **Closed sinks silently accepted work.** `KafkaSink` produced into a batch nothing would flush,
  `GooglePubSubSink` appended a future nothing would resolve, and the Redis sinks *succeeded* by
  reconnecting a client they had just disconnected.
- **`os.fork()` was unhandled anywhere.** A forked child inherited a worker whose drain thread does
  not exist (six events never delivered, `health()` clean on every documented alert term) and locks
  held by threads that do not exist (**19 of 60 children hung permanently** inside `info()`, on the
  application's own thread). Both are repaired, in the child only.
- **The sink every event was going to could be closed by nobody.** The record of which sinks were
  owed a close was a single slot, so arming a second discarded the first. Measured with every call
  sequential on one thread: the live sink's `close()` never ran and its buffer never delivered.
  Then, once that record became a set, `shutdown()` cost one slow close *times* the number owed —
  2.00 s for one, 8.02 s for four. Both are fixed; 200 owed sinks went 11.4 s → 0.06 s.
- **Diagnostics could leak your data.** Twelve of the library's stderr sites printed
  `repr(exception)`, and a psycopg repr reprints the statement *and* its bound parameters. Every
  line the library writes about itself now names an exception by type only.

## Upgrading from `0.10.x`

Ordered by how likely each is to reach you, not by how loudly it lands — items 18 to 22 are the
quietest in the list and are last. Read to the end.

**1. `Health` is a frozen dataclass, not a `NamedTuple`.** `len(h)`, `h[0]` and
`queued, dropped, failed_batches, stopped_reason = health()` — the four-way unpack that worked
against `0.10.x` — now raise `TypeError`. **Read it by attribute.** The same
applies to `SinkLosses`. This is the change most likely to break an upgrade, and it was made
*before* 1.0 precisely so the eight fields you are gaining — none of them present in `0.10.x`,
which had the same four as `v0.7.0` — `sink`, `retired`,
`submitted_after_shutdown`, `incomplete_swaps`, `closing_sinks`, `inherited_sink`, `orphan_lost`,
`in_span_lost` — could be plain appends with no position to preserve.

**2. `Config`, `ContinueResult`, `FlushResult`, `Health` and `SinkLosses` are all keyword-only
dataclasses.** Positional construction now raises `TypeError`. Item 1 already covers unpacking a
`Health`; this is the other half, and it was done before 1.0 precisely so field order never
becomes part of the frozen contract. If you construct `SinkLosses` inside your own sink's
`losses()`, *If you wrote your own sink* below already tells you to use keywords — that is the
same rule stated once, not twice. Three smaller changes ride the same spec: `context.__all__` is
trimmed to six names — `current_baggage_header`, `current_trace_context`, `current_traceparent`,
`get_baggage`, `reset_context`, `set_baggage` — with the other five withdrawn from the list but
still importable, so only `from log_foundry.context import *` loses anything. `trace(defaults=…)`
now takes its copy at decoration rather than reading your mapping live per event, so mutating it
afterwards no longer reaches later spans, and the parameter widened from `dict` to `Mapping` so a
typed `dict[str, str]` is accepted either way. And the seven HTTP platform sinks (`DatadogSink`,
`LokiSink` and their siblings) now type their keyword arguments through `Unpack[TypedDict]`, so
`DatadogSink("k", timeout="not-a-float")` is a `mypy` error instead of a first-request failure —
a typed consumer's build can newly fail here; that is the point. Additive and safe:
`GroupIdSource`/`DedupIdSource` (`SQSSink`'s `message_group_id`/`message_deduplication_id`) and
`Backend` (`SentrySink`'s `backend`) are now exported from their sink modules, and `flush_sink`
plus `DEFAULT_SWAP_TIMEOUT` from the top level.

**3. A bad sink argument is now refused where it is written, not where it first breaks
delivery.** The library floors a value that already worked, refuses one that was already broken,
and refuses a brand-new argument — all of it at construction, meaning import or process start
rather than first emit. That is the point: a bad argument used to surface as an uncounted raw
exception at first delivery, forever; now it means an upgrade can fail at process start where
`0.10.x` started fine. Every HTTP-family sink, and every subclass built on it, refuses an
unusable `timeout`, CR/LF in a header name, a header value or a bearer token, a URL whose scheme
is not `http`/`https`, a host-less URL, `max_batch_bytes` and `body_format`; a non-number where a
number is required is a `TypeError` naming the argument. `SocketTransport` refuses `timeout`, an
out-of-range `port`, and `max_datagram_bytes`. `ClickHouseSink` and `PostgresSink` refuse
`chunk_size`. `RotatingFileSink` refuses a non-positive `interval`, `when=None` included.
`LogstashSink` refuses socket-only arguments given beside `url=`, and HTTP-only keywords given
beside `host=`/`port=`. `SyslogSink(app_name=)` and `ElasticsearchSink(index=)` refuse whitespace
or an empty string. `NATSSink` refuses a non-positive `max_reconnect_attempts` and `servers`
given beside `client=`. `RedisStreamsSink`, `RedisListSink` and `MemorySink` refuse `maxlen`. Not
everything tightened the same way: `RotatingFileSink`'s `max_bytes<0` and `backup_count<0` still
clamp to `0`, as they already behaved; `GooglePubSubSink(overflow_timeout=)` and `max_retries`
across the retrying sinks are floored rather than refused, so nothing breaks there.

**4. `@trace` now refuses at decoration what it cannot trace, and the big one is a generator
function.** On `0.10.x`, `@trace` on a generator traced the *call*, not the iteration: the span
opened and closed before the body ran — measured, `['span.start', 'span.end']` before the first
`next()` — and every event the body logged became an orphan on a fresh trace, silently wrong. It
is now a `TypeError` at decoration, reading `@trace cannot trace the iteration of the generator
function <name>: its body runs after the wrapper has returned, so the span would close before it
starts. Trace the consumer instead: the function that iterates it`. It catches sync and async
generator functions, a `functools.partial` of one, one behind `@contextmanager` or `@lru_cache`
or any `functools.wraps` wrapper, and an instance whose `__call__` is one. A plain function that
merely *returns* a generator object without advertising it is indistinguishable at decoration and
stays uncaught — a stated limit, not a gap. Three smaller refusals moved to decoration in the
same spec, each formerly a call-time failure or no failure at all: `@trace` applied above
`@classmethod`/`@staticmethod` — the message tells you to swap them; `@trace("checkout")`, the
slip that meant `name="checkout"` — the message says so; and anything else not callable, or a
non-`str` `name=`. One fix rides along, worth a sentence: a `functools.partial` or a callable
instance now traces under its type name, computed once at decoration — before, `fn.__qualname__`
was read per call inside the wrapper, so `@trace(functools.partial(f, 1))()` raised
`AttributeError` into the caller at call time.

**5. `configure()` now refuses a `service`, `version` or `env` it cannot encode.** Each is
checked before the sink is stamped: a non-`str` is `TypeError: <name> must be a str, got
<type>`, and one carrying a lone surrogate is `ValueError: <name> must be encodable as UTF-8; it
carries a lone surrogate`. The wire-format half of the same fix changes what lands downstream
even where you never hit the new refusal: no string leaves event assembly unencodable any more —
a lone surrogate is replaced by U+FFFD with `truncated` set on the event. Before, it survived
assembly and cost the **whole batch** on any sink binding a raw `str` column (`SQLiteSink`,
`PostgresSink`, `ClickHouseSink`). If you match on the old byte sequence downstream, update the
query.

**6. `MongoDBSink`, `RabbitMQSink` and `ClickHouseSink` each gained a bound their driver did not
have.** `MongoDBSink` applies `socketTimeoutMS=30000` only when neither `socket_timeout=` nor the
URI's query names one — `pymongo`'s own default is `None`, so a read that never returned held the
drain thread for good; `server_selection_timeout` is exposed but the driver's finite 30 s default
is left alone. `RabbitMQSink` sets `blocked_connection_timeout=30` inside `_connect` — URL and
no-URL constructors alike, and on every reconnect — only when the URL query named none, and an
explicit keyword still overrides it; `pika`'s own default is `None`, so a broker under a memory
or disk alarm blocked every publish indefinitely. `socket_timeout` (10 s) and `stack_timeout`
(15 s) are exposed on the same terms, at `pika`'s own already-finite defaults. `ClickHouseSink`
exposes `send_receive_timeout`, forwarded only when given — the driver's 300 s default is finite
and deliberately left alone. Each of the three is refused beside an injected client. **If you run
RabbitMQ, verify this against your broker rather than take it on trust:** the behaviour was read
from the installed `pika` (1.4.4) and not executed against one. The reader-facing point: if you
run Mongo or RabbitMQ and relied on an unbounded wait, you now get a 30 s bound you did not ask
for, and the keyword to change it.

**7. `flush()` and `continue_trace()` return objects, not booleans.** `FlushResult` and
`ContinueResult` are truthy or falsy with a `reason` naming *why*. `if lf.flush():` is unchanged;
`lf.flush() is True` no longer holds. A one-bit return could not have grown a reason later
without silently changing what `if flush():` means.

**8. `log_foundry.sinks.util` is deleted, with no alias.** Import `MemorySink` from
`log_foundry.sinks.memory`, `NullSink` from `…sinks.null`, `StderrSink` from `…sinks.stdout`.

**9. `continue_trace()` is one-shot.** It applies to the next root span and does not survive it.
Previously one call kept every later root span in the inbound trace; now the second and third mint
fresh `trace_id`s. There is no exception and no counter — distributed traces just get shorter.
**If you fan out to sibling root spans, call `continue_trace()` once per item**, or put a single
`@trace` entry point above them.

**10. A failing sink no longer reaches your code.** `@trace` and the level emitters absorb an
`Exception` from the sink and report it as one stderr line plus a `health()` counter. If a test or
an error path relied on a sink fault propagating, it now passes silently. `KeyboardInterrupt` and
`SystemExit` are still propagated — those are the operator's intent, not the sink's failure.

**11. `configure(sink=...)` closes the sink you gave it earlier, and can block.** The swap drains,
closes the previous sink, and points delivery at the new one — bounded at **5 seconds for the whole
call**, a bound no keyword lets you change. A sink object you still hold a reference to is closed
out from under you, so `Sink.close()` must be idempotent. Budget for those 5 seconds if you
reconfigure on a startup path.

**12. A sink that released transport state refuses work after `close()`,** raising
`SinkDeliveryError` — newly exported, so `from log_foundry import SinkDeliveryError` — where it
previously accepted the batch and lost it silently. That includes sinks needing no optional extra
at all: `FileSink`, `RotatingFileSink`, `SQLiteSink`, `SyslogSink`, and `LogstashSink` on its
`tcp`/`udp` transports. Teardown code that logs after closing its sink will see this without
installing anything.

A sink holding no transport keeps accepting, and that is the same rule rather than an exception to
it: `StdoutSink`, `StderrSink`, `MemorySink` and `NullSink` release nothing, and neither does
`LogstashSink` in HTTP mode or any of the HTTP platform sinks (`DatadogSink`, `LokiSink` and their
siblings), which open a connection per request. Making those refuse would invent loss where the
write would have landed.

**13. Every stderr diagnostic was reworded.** All of them now go through one module, and the
detail moved: `worker thread stopped on X` became
`absorbed a failure while draining the log queue (X); worker thread stopped; …`. **Log-scraping
alerts keyed on the old strings will go quiet** — the phrase `worker thread stopped` survives, so
an alert on that still fires, but one on `worker thread stopped on ` no longer does. Key them on
`health()`, which is the supported interface.

**14. Constructor changes.** `SQSSink`'s injected client is keyword-only —
`SQSSink(queue_url, client=…)`. `SentrySink` injects through `client=` with no alias for the old
`sdk=`, takes a new `backend=` selector, and now *rejects* arguments a given backend cannot use
rather than ignoring them. `RotatingFileSink(backup_count=1)` is the new default; the old `0`
destroyed a generation at every rollover. `LogstashSink`'s HTTP mode defaults to
`body_format="json_array"` — breaking for anyone who configured Logstash's
`additional_codecs` workaround, who must now pass `body_format="ndjson"`.

**15. `shutdown()` takes a `timeout`, defaulting to 30 seconds, where it previously waited
indefinitely.** A process with a slow sink that always drained fully now stops draining at 30 s and
loses the remainder. `shutdown(timeout=None)` restores the old unbounded wait; the default is
exported as `DEFAULT_SHUTDOWN_TIMEOUT`. An expired shutdown deliberately leaves the sink **open** —
the drain thread may still be inside its `emit` — and reports a `stopped_reason`.

**16. `Config` is frozen and `get_config()` returns a copy.** Rebinding a field on it raises
`FrozenInstanceError` instead of silently changing the library's behaviour. Read the bound
deliberately: the copy is **one level deep**, so a nested value inside `defaults` is still shared
and mutating it in place still reaches the library, with no error. `configure()` is the supported
way to change configuration. The same one-level bound applies to `get_baggage()`; deep-copying
arbitrary caller objects inside an accessor that must not raise would trade a narrow sharing
limit for a wide new failure.

**17. `Sink.emit` and `Sink.close` are `@abstractmethod`.** A subclass that misspells one now
fails to instantiate instead of inheriting an empty body, returning `None` from `emit`, and losing
every event with all counters at zero.

**18. Two lifecycle paths that used to fail silently now report.** A `shutdown()` first called on
a daemon thread let `atexit` return through an inline `close()` that was still running, and
process exit killed it — measured at twelve buffered events lost with nothing on stderr; a caller
that did not claim the close now waits for it. And a process that cannot start a drain thread at
all used to report `in_span_lost=0` over total loss, where it now counts the events.

One consequence of item 15 worth stating separately, because it changes what `flush()` reports.
**`ok=True` still means the sink took them** — that guarantee is untouched. What changed is the
falsy side: a bounded `shutdown()` that gives up on a drain now answers the `flush()` calls already
waiting on it, rather than leaving them parked on a thread it has given up on. A
`flush(timeout=None)` parked that way previously waited forever. It is still unbounded on its own,
so passing a timeout you are willing to wait remains the advice. `"abandoned"` has widened to
match: it no longer implies the drain reached a verdict on that batch, because the drain may still
deliver those events afterwards.
The verdict is traded, not the delivery.

**19. Non-finite floats render differently on the wire, and the old form was not valid JSON.**
`float("nan")`, `inf` and `-inf` now emit as `"<float: nan>"`, `"<float: inf>"` and
`"<float: -inf>"`, with `truncated: true` on the event, mirroring the existing rule for an
over-long integer. Before, a non-finite **value** passed through untouched and `json.dumps` wrote
the bare tokens `NaN`, `Infinity` and `-Infinity` — Python emits them by default, but they are not
JSON, and a strict parser downstream rejects the line. A non-finite **mapping key** went through
`str()` instead and produced a bare `"nan"`: parseable, but the type was lost and no marker was
set. Both are now the quoted placeholder. If you match on the old form, update the query — and if
you had a downstream parser rejecting lines it could not read, this is why.

**20. `PostgresSink(connect_timeout=…)` overrides any `connect_timeout` in your DSN**, and
defaults to 5 seconds. If you set it in the connection string, it is now replaced rather than
respected.

**21. `fields` became a reserved parameter name on the five level emitters, and this one is
quiet.** The signature went from `info(message, *, echo=False, **fields)` to
`info(message, *, echo=False, fields=None, **kv)`. A call that used `fields` as an ordinary field
name is now reinterpreted rather than rejected: `lf.info("m", fields={"a": 1})` used to log
`{"fields": {"a": 1}}` and now logs `{"a": 1}` — reshaped, no error — and
`lf.info("m", fields="a string")` used to log that string and now **drops it**, with one stderr
line and every `health()` counter still at zero. Nothing warned anyone off the name; `0.10.x`'s
README never called it reserved. **The remedy is the escape hatch itself:**
`lf.info("m", fields={"fields": "a string"})` puts the key back where it was. The keyword form is
also what you now use for any key colliding with a reserved name.

**22. `health().sink` and `health().inherited_sink` now answer from one place — the
configuration — on both delivery paths and in a forked child.** Before, `sink` reported against
one delivery path and `None` against the other for the same sink, and `inherited_sink` read the
owed-close record's last entry, which could name a sink this process had already **stopped**
delivering to. This is a fix, not a break — but if you assert on either field, it now reports
where it previously did not. This is the quiet end of the list.

Smaller: `max_retries` is floored at 0 across the retrying sinks; UDP syslog resolves through
`getaddrinfo`, so an IPv6-only host that used to fail now works; `RotatingFileSink` measures its
rotation interval on `time.monotonic()`, so a backward clock step no longer defers rotation; and
`NATSSink`, `KafkaSink`, `PostgresSink` and `GooglePubSubSink` all gained real bounds and the
keywords to set them.

## If you wrote your own sink

A class with just `emit` and `close` still satisfies the protocol. `sinks/base.py` now states the
full contract worth implementing: raise when you can prove nothing landed, report partial loss
through `losses()` rather than raising, tolerate concurrent `emit`/`close`, and refuse after
`close()` if you released transport state. Four optional members are probed by name rather than
required — `losses()`, `flush()`, `reacquire_after_fork()`, and the attribute the library assigns
for interruptible backoff, which is `log_foundry_stop_signal` and **not** `stop_signal`: a
prefixed name cannot silently overwrite one your own sink already uses.

**If you subclass `HTTPSink`, do not override `emit`.** It became a template method that owns
the chunk loop this release exists to add, and a subclass overriding `emit` bypasses it — which
is exactly how five shipped sinks came to send a 5,980-event exit backlog as one request. Extend
through `_render`, `_body` and `_handle_response`. A lint enforces this for the sinks in this
repository and cannot reach yours.

**If you construct `SinkLosses` inside `losses()`, use keywords.** `read_losses` deliberately
swallows an exception from that accessor so a broken reporter cannot take `health()` down — which
means a `TypeError` there does not surface as an error, it silently degrades your sink's loss
reporting to `None`.

If you fork, build a connection-holding sink **in the worker process**, never before the fork.
