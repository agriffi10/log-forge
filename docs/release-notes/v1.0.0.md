**The first stable release.** The public API is now under semantic versioning: everything in
`log_foundry.__all__`, the `Sink` protocol, and every shipped sink class keep their behaviour
across `1.x`.

`1.0.0` is not a feature release. Every public signature has been stable since `v0.7.0` — an AST
diff across that range shows zero removals, zero renames, and three added keyword-only parameters.
What changed is the part that decides whether you can trust a logging library: its failure modes.
A ten-spec audit arc (SPEC-024..033) went through every path where the library could lose an
event, fail its caller, or report health it could not back up, and closed them.

**Signatures did not change, but behaviour did.** Read
[Upgrading from `0.10.x`](#upgrading-from-010x) before you bump — several of the changes are
silent, and two of them can quietly shorten a distributed trace or swallow an exception you were
relying on.

## What the arc fixed

Each of these was a real, measured defect:

- **Per-request context leaked between requests.** Baggage and an adopted trace context were
  written into `contextvars` and never taken back out, so on a thread serving requests
  sequentially one request's `user_id` reached the next request's events, and a warm container
  kept joining a trace whose process had exited. Both are now released when the root span closes —
  baggage *restored* to what preceded the span, an adopted context *cleared*, because an inbound
  context is a one-shot handoff rather than a process default.
- **Sinks that lost everything reported success.** A dead syslog socket produced `flush() == True`
  and an all-zero `health()` while every message was lost. A sink that can prove it delivered
  nothing now raises, so the retry engages and the loss is counted; one that absorbed partial loss
  reports it through `health().sink`. Three cases deliberately stay quiet — an unadjudicable batch
  response, a rejected SQS sender fault, and an oversized event — because there a retry could
  duplicate rather than recover.
- **A sink's backoff paused all delivery, including through `shutdown()`.** `HTTPSink` passed a
  server-supplied `Retry-After` straight to `time.sleep`: measured, `Retry-After: 8` at the default
  `max_retries=3` blocked `shutdown()` for 22.01 s across its three waits, and `86400` would have
  stalled logging for a day. Every wait is now bounded, clamped, and cut short by a shutdown.
- **Concurrent emitters could corrupt a sink.** A level call with no active span emits on your
  thread, against the same sink object the worker is draining into. Unlocked, `SQLiteSink` did not
  merely lose rows — it killed the interpreter with a bus error. The sinks holding transport state
  now lock.
- **Closed sinks silently accepted work.** `KafkaSink` produced into a batch nothing would flush,
  `GooglePubSubSink` appended a future nothing would resolve, and the Redis sinks *succeeded* by
  reconnecting a client they had just disconnected. They refuse now.
- **Two lifecycle mistakes were invisible.** Logging after `shutdown()`, and a late
  `configure(sink=...)` that updated what `get_config()` reported while every event continued to
  the old sink (measured: sink A got 4 events, B got 0, the config claimed B). Both are now
  reported, and the swap actually swaps — on the buffered path and, as of the last spec in the arc,
  on the synchronous one too.
- **Diagnostics could leak your data.** Twelve of the library's 28 stderr sites printed
  `repr(exception)`, and a psycopg repr reprints the statement *and* its bound parameters. Every
  line the library writes about itself now names an exception by type only.

## Upgrading from `0.10.x`

No import, name or signature changed. These are behaviour changes, ordered by how quietly they
break you.

**1. `continue_trace()` is now one-shot.** It applies to the next root span and does not survive
it. Previously one call kept every later root span in the inbound trace; now the second and third
mint fresh `trace_id`s. There is no exception and no counter — distributed traces just get
shorter. This is deliberate: the old behaviour meant a warm container joined the first caller's
trace forever. **If you fan out to sibling root spans, call `continue_trace()` once per item**, or
put a single `@trace` entry point above them. Adopting *outside* a span and then dispatching into
an `asyncio.Task` needs `reset_context()` — `contextvars` cannot write to a parent context, so that
one is closed by documentation rather than by code.

**2. A failing sink no longer reaches your code.** `@trace` and the level emitters absorb an
`Exception` from the sink and report it as one stderr line. If a test or an error path relied on a
sink fault propagating, it now passes silently. Relatedly, a failure *before* the function body
degrades to an **untraced call** — the function runs and returns normally, emitting no span events
at all. `KeyboardInterrupt` and `SystemExit` are still propagated.

**3. `configure(sink=...)` now closes the sink you gave it earlier, and can block.** The swap
drains, closes the previous sink, and points delivery at the new one, bounded at 5 s for the whole
call. Two consequences: a sink object you still hold a reference to is closed out from under you,
and `configure(A)` → `configure(B)` → `configure(A)` closes A twice — the previous sink must not be
handed back, and `Sink.close()` is required to be idempotent.

**4. Fifteen sinks refuse work after `close()`,** raising `SinkDeliveryError` — including core,
no-extra ones: `SyslogSink`, `LogstashSink`, `FileSink`, `RotatingFileSink`, `PostgresSink`,
`SQLiteSink`. Teardown code that logs after closing its sink now sees an error where it previously
saw silence and total loss.

**5. Every stderr diagnostic was reworded.** All 28 sites now go through one module, so
`worker thread stopped on X` reads as
`absorbed a failure while draining the log queue (X)`. **Log-scraping alerts keyed on the old
strings will go quiet.** Key them on `health()` instead, which is the supported interface.

**6. Unpacking `Health` breaks again.** It gained five fields (`sink`, `retired`,
`submitted_after_shutdown`, `incomplete_swaps`, `closing_sinks`), so a four-way unpack —
`queued, dropped, failed, reason = health()` — now raises `ValueError`. It is a `NamedTuple` and
grows only by **appending**, so every existing field keeps its position. **Read it by attribute.**
Appending is the only change `1.x` will make to it. Note also that `health().sink` counters reset
when the sink is swapped, so a polling monitor can see them go backwards.

**7. `shutdown()` takes a `timeout`,** defaulting to 30 s. An expired shutdown deliberately leaves
the sink **open** — the drain thread may still be inside its `emit` — and reports
`stopped_reason == "ShutdownTimeout"`, a new value for that field.

**8. A process that only logs outside a span now closes its sink at exit.** Such a program builds
no worker, so nothing previously owned that close; an `atexit` handler now performs it exactly
once.

Smaller: `max_retries` is floored at 0 across the retrying sinks; UDP syslog resolves through
`getaddrinfo`, so an IPv6-only host that used to fail now works; `RotatingFileSink` measures its
rotation interval on `time.monotonic()`, so a backward clock step no longer defers rotation.

**A sink you wrote against `0.10.x` still works** — a class with just `emit` and `close` satisfies
the `Sink` protocol, and the optional `losses()` and `stop_signal` are probed by name rather than
declared. `sinks/base.py` now states the full contract worth implementing: raise when you can prove
nothing landed, tolerate concurrent `emit`/`close`, and refuse after `close()` if you released
transport state.
