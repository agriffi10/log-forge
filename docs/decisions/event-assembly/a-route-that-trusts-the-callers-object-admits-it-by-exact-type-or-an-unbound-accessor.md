---
type: Decision
title: "A route that trusts the caller's object admits it by exact type or an unbound accessor"
description: "Any route that returns the caller's object, or lets its method decide a measurement, tests `type(v) is T` or converts through `int.__int__`/`float.__float__` first; builtin text, bytes and containers are routed by real type; `isinstance` stays only on render-through routes (proxies). A container key is coerced as a value and written as the JSON of the result, never its `repr`. (SPEC-063)"
---

**A route that trusts the caller's object admits it by exact type or an unbound accessor** — `isinstance` consults `__class__` and `kind in _PLAIN_SCALARS`, a set of types, consults the type's `__hash__` and `__eq__`, so a caller's object chose which rule it met. Measured at `71e42dd`, an object whose `__class__` returned `bool`, one whose `__class__` returned `float` with a `__float__` of `1.0`, an instance of a class whose metaclass hashed as `int` and compared equal to it, and an `Enum` member whose `.value` was the float impostor each reached the assembled event as the object itself, and a sink's bare `json.dumps` raised. A genuine `float` or `int` subclass reached the event as the subclass. So a route that returns the caller's object, or lets its method decide a measurement, admits it only by an identity test on the real type (`kind is bool`; `bool` cannot be subclassed) or by converting it first through the unbound `int.__int__` or `float.__float__`, which return an exact number for a genuine subclass and raise `TypeError` for an impostor, now a `<unserializable: T>` placeholder naming its **real** type. The float key branch and the Enum member routes follow the same rule, and `_key` admits an integer key by `type(key) is not bool`, because an `int` subclass claiming `bool` skipped SPEC-057's integer-key pricing: with the digit limit lifted, a 3,000,000-digit key was rendered whole in 0.58 s of CPU where a plain one was a placeholder in 0.0 s.

**Builtin text, bytes and containers are routed by real type.** The Enum branch is entered only by a real `Enum` or by an object whose real type is no builtin text, bytes, container or number, because its fallback is `str()` (a real `tuple` claiming `Enum` wrote `(SECRET,)` before that test). After the `int` and `float` handling, which converts or refuses what it admits, and ahead of the render-through branches, a value whose real type subclasses `str`, `bytes`/`bytearray`, `dict`, or `tuple`/`list`/`set`/`frozenset` goes to its own route by `issubclass(type(value), …)`, which `__class__` cannot reach. Otherwise a real tuple claiming `UUID` or `Decimal` reached `str()`, the builtin `repr`: measured at `71e42dd`, it hung on a shared `frozenset` DAG applied forty times, wrote an object's `repr` into the event, and a real `bytes` subclass claiming `Decimal` cost a 256 MiB peak.

**`isinstance` stays, on purpose, for the render-through routes** — `Mapping` and `Sequence` iteration, `isoformat()`, `str()` of a `UUID` or `Decimal`, the Enum fallback — only for an object whose real type is none of those builtins. What they write is the library's own text, an exact `str`, `dict` or `list`, and transparent proxies (`wrapt.ObjectProxy`, Django's `SimpleLazyObject`) set `__class__` legitimately and render correctly through them today; switching them to `type()` would turn a proxied `dict` or `datetime` into a placeholder. A proxy of a scalar never worked.

**A type's name is read where it is stored.** `_type_name` reads `_STR_STR(type.__dict__["__name__"].__get__(type(value)))`, so a metaclass `__name__` property can neither raise nor rename a placeholder, and the unbound `str.__str__` returns an exact `str` where `type.__name__`'s setter accepted a `str` subclass whose `__format__` hijacks the f-string that embeds it. `model`'s `error` sub-document and stack fallback reuse it, and `_diag.absorbed` writes the same read, being a leaf: at `71e42dd` a raising metaclass `__name__` cost a span its events and silenced the announcement of a counted loss.

**A container key is coerced as a value and written as the JSON of the result.** A key whose real type subclasses `tuple`, `list`, `dict`, `set` or `frozenset`, and not `Enum`, was rendered by `str(key)`, which recurses through a shared member once per path before any budget applies. Measured at `71e42dd`, `f = frozenset({f, (f, i)})` applied 14, 16, 18 and 20 times as one key cost 0.008, 0.034, 0.142 and 0.572 s of CPU, doubling per level, and a tuple key of 64 references to one 1 MiB string rendered 64 MiB before it became `<size limit>`. It is now walked by `mapping()` or `members()` at the entry's value depth, never through `_dispatch`, spending one node for itself and one per member per path and charging its members to the byte budget as values are; its text is `json.dumps(coerced, ensure_ascii=False)` clipped to `max_value_bytes`, not charged a second time, so `(1, 2)` is the key `"[1, 2]"` and no member's `repr` is written. A key that stops the pass is written as the stop placeholder for key and value both. A `bytes` or `bytearray` key is priced at `4 * len + 3` before it is rendered, and one longer than about a quarter of the remaining budget becomes `<size limit>` unrendered.

**Rejected:** keeping the `repr` behind a pre-pricing walk, which needs a second implementation of the pass's traversal that must agree with the first and still writes each member's `repr` into the key against arch §6; a type-name placeholder for a container key, which collapses distinct keys onto one and replaces an ordinary key with something that looks hostile; routing a container key through `_dispatch`, whose render-through branches hand a claim-bearing tuple back to the builtin `repr`; pricing a bytes key at its length alone, which still rendered a 64 MiB repr of a 16 MiB key. **Stated costs, not open:** a container key's JSON text collides with an equal-membered list key a caller `Mapping` can yield; an object key keeps its own `str()`, which for a default object is its `repr`; a transform's types-only coercion renders container keys by the same rule outside the budgets, and its accepted DAG cost extends to a DAG key. **Do NOT** route a value or a key on `isinstance` or on set membership of a type where the result is the caller's object.
