---
type: Decision
title: "A destination's refusal is repaired at the sink and marked as assembly marks"
description: "Assembly cannot know the destination, so a value it allows and a destination refuses is repaired by that sink, on a copy, and delivered: `PostgresSink` turns every U+0000 into U+FFFD, `MongoDBSink` an integer outside int64 into `<int: ~N digits>` and a NUL in a key into U+FFFD, each marked `truncated`, never counted; `SQLiteSink` and `PostgresSink` bind a projected column value their driver refuses as its JSON text, the event unchanged and unmarked. Only a refusal the pipeline can produce, measured against the real service, decidable from one event. (SPEC-069)"
---

**Repair what the destination refuses, and deliver the event.** Invariant 8 makes every assembled event valid JSON, but two destinations refuse values valid JSON allows, and those values are reachable from `@trace`, `info()` and `configure()`: PostgreSQL's JSONB and its text columns refuse U+0000 (JSONB cannot hold `\u0000` because `text` cannot), and MongoDB's BSON refuses an integer outside `[-2**63, 2**63-1]` and a NUL in a key name. Each refusal cost the whole batch, retried to no effect — Postgres commits every chunk in one transaction, so one bad row rolled back all of them — and `configure(service="s\x00x")` lost every event to Postgres, since the stamps bypass assembly. Andrew chose on 2026-11-04 that the sink repairs only what its destination refuses and delivers the event, carrying SPEC-058's principle (a bad event costs only itself) to the point where nothing is lost. Only the sink can take this step, because only the sink knows its destination; assembly's promise is unchanged.

**The admission rule.** A refusal is repaired when the pipeline, `configure()` or a post-assembly path can produce it, a real driver or service was measured refusing the whole bulk call for it, and the sink can decide it from that one event alone. PostgreSQL's U+0000 and MongoDB's two refusals meet it. A refusal nobody has measured is not repaired; an event that still fails after the repair is unencodable and is dropped alone, counted and announced (*An event a sink cannot encode costs only itself*).

**How each is detected and repaired.** Both run inside the sink's encode function (`sinks/_encode.py`), on a **copy** rebuilt container by container, so the batch is never mutated: a `MultiSink` sibling and the worker's retry are handed the original objects.

- `PostgresSink` matches the JSON text it already builds against `NUL_ESCAPE`, `(?<!\\)(?:\\\\)*\\u0000` — a `u0000` whose preceding backslash run has odd length — so a clean event costs one search and the six characters `\u0000` written as text, which JSONB accepts, cost no walk. The search is a filter, not the decision: `repair_nul` walks for a real U+0000 and returns `None` when it finds none, so it is the walk that leaves the lookalike alone. On a match `repair_nul` replaces every U+0000 in every string value and key, at every depth, with U+FFFD before encoding again; the projected text columns are top-level values of the same event, the `service`, `version` and `env` stamps included, so one repair covers the JSON and the columns with one representation.
- `MongoDBSink` asks the driver's own `bson.encode`, imported lazily on the first `emit` that reaches the check and read by name, never at construction: a `bson` that is missing or has no `encode` disables the check rather than raising, so an injected client with no driver installed is never repaired. When it refuses, `repair_bson` replaces an out-of-range integer with assembly's too-large-number placeholder through `sanitize.int_placeholder` — factored out of `sanitize._int_text`, with a test holding `_Coercer`'s two inline copies and `_otel._int_digits` equal to it — and a NUL in a key with U+FFFD; a NUL in a *value* is left, because BSON accepts it, and a `bool` is never read as an integer. The existing `json.dumps` size measure still decides the 16 MB drop.

**A projected column the driver cannot bind is bound as its JSON text, and nothing is marked.** `SQLiteSink` and `PostgresSink` project a few top-level values into text columns beside the event's JSON, and a value there the driver cannot bind cost the whole batch: `sqlite3` refuses a `dict`, a `list` and an integer outside the signed 64-bit range (that one a bare `OverflowError`, nothing counted), and psycopg a `dict` and a `list` that is mixed, ragged or holds a `dict`, each measured at `a8e91fac` against `sqlite3` and PostgreSQL 17.11. A `TransformSink` can put any of them in a column, so the admission rule holds. `sinks/_encode.column_value` binds a container, and for SQLite an out-of-range integer, as its JSON text, the text the event column already holds for it. Every container takes the rule, including the lists psycopg did bind as array literals (`{1,2}`), so a column holds one representation whichever sink wrote it; Andrew chose this on 2026-11-13 over a rule predicting which lists psycopg adapts, which would mirror the driver's internals and leave a column holding two forms. The event itself is not changed, so it carries no `truncated` and nothing is counted: the column is a filter beside the record, not the record.

**A lone surrogate is dropped alone, not repaired.** JSONB refuses its `\ud800` escape and psycopg the string in a text column, so one cost `PostgresSink` the whole transaction, measured at `a8e91fac`; in a SQLite projected column `sqlite3` refuses it too. Assembly replaces a lone surrogate, `TransformSink` coerces one and `configure()` refuses one in a stamp, so only a direct `emit` brings one, and by the admission rule it is not repaired: `sinks/_encode.refuse_surrogate` (PostgreSQL, the whole event) and `column_value` (a projected column) raise, and the encode step drops the event alone, counted and announced. A surrogate pair held as two code points is not lone: `json.dumps` writes it as an emoji's two escapes, which JSONB accepts, so `refuse_surrogate` lets it through, while in a projected column neither driver can encode it and `column_value` drops it. SQLite's event column stores the escape, so a surrogate outside SQLite's projected columns lands. A non-finite float is the same case for `PostgresSink`: a bare `json.dumps` writes `NaN` or `Infinity`, which JSONB refuses (measured at `c357bbf2`, the batch lost), and assembly and `TransformSink` write `<float: nan>` instead, so `PostgresSink` builds its text with `allow_nan=False` and drops that event alone.

**Marked as assembly marks, and not a loss.** A repaired copy carries `truncated: True`, the mark assembly sets for a lone surrogate replaced by U+FFFD and for its too-large-number placeholder; an event the repair did not change gets no `truncated` key and is byte-identical to before. Two keys that repair to one text keep the later value, marked, as assembly resolves two hostile keys on one placeholder. Nothing is counted and nothing is announced, as with assembly's coercion (invariant 2).

**Do NOT** repair in assembly what only one destination refuses; do NOT mutate the batch; do NOT repair a refusal no real service was measured making; do NOT repair the JSON text by substring; do NOT import `bson` at construction or let a missing one raise; do NOT count or announce a repair. ~~Out: a lone surrogate reaching `PostgresSink` through a direct `emit` (assembly and `TransformSink` replace them, so it is outside the pipeline and unmeasured), and SQLite column values that cannot be bound.~~ Superseded by the SPEC-069 follow-up fix of 2026-11-13: both measured and handled, as *A projected column the driver cannot bind* and *A lone surrogate* above say. Out until after 1.2.0, by Andrew's choice of 2026-11-13: `ClickHouseSink`, whose projected columns `create_table` provisions typed (`Nullable(String)`, and `Nullable(Float64)` for `duration_ms`); a value one refuses — anything but a `str` or `None` in a string column (`AttributeError`), a lone surrogate in one (`UnicodeEncodeError`, direct `emit` only, since `TransformSink` replaces it), or a `str`, `list` or `dict` in `duration_ms` (`DataError`) — which only a direct `emit` or a `TransformSink` rewriting a projected key brings, fails the chunk's one `insert`, not retried, so every event in the chunk is lost, counted and announced (measured at `1545113c` against ClickHouse 24 and clickhouse-connect 1.4.2). Invariant 8 records it as an exception. (SPEC-069 FR-003)
