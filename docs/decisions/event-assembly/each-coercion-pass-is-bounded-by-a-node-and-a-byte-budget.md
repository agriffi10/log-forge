description: "except a transform's types-only coercion, which stays unclipped; a pass visits at most 131,072 values and charges at most 16 MiB of text; the value that crosses either becomes a marked `<node limit>` or `<size limit>` and the walk stops, so walk order decides what is sacrificed. ---

**Each coercion pass is bounded by a node and a byte budget** — `build_event` runs on the caller's thread on both delivery paths, and the pass bounded how deep, how wide and how long a *value* may be but not its own total work. A shared sublist is a DAG, not a cycle, so the ancestor check never fires on `y = [y] * 16` applied seven times and the pass made 16^7 visits; the same walk over an 8 KiB string shared across every one of 131,072 values is a gigabyte of event. So a pass visits at most **131,072 values** (`sanitize._MAX_NODES`) and charges at most **16 MiB** of text (`sanitize._MAX_RENDERED_BYTES`); the value that would cross either becomes `<node limit>` or `<size limit>`, `truncated` is set, nothing after it is visited, and every open container ends after the member it was writing. (SPEC-057 FR-001, FR-002) **The numbers:** 131,072 is twice a fully populated two-level structure at the default `max_keys` (256 × 256), so a wide but ordinary event is not cut, and no larger, so the worst pass stays small; 16 MiB is far above most sinks here (SQS takes 256 KB) and equal to `MongoDBSink`'s document limit, so through assembly one string over it becomes `<size limit>` before that sink's check sees it (escaping or the envelope can still reach the check), and reaching it legitimately takes at least 2,048 full strings at the default 8 KiB ceiling, so in practice it only catches amplification. `json.dumps` escapes a control character as six bytes, so the serialised worst case is about six times the byte budget per pass, and a boundary event takes two passes, `build_event`'s and `backfill_baggage`'s.

A transform's coercion is outside both budgets (`_Coercer(budgeted=False)`). SPEC-058's types-only pass promises not to clip, and with the budgets in it a 20 MiB string became `<size limit>` and every later key, envelope keys included, was dropped, with every test green. Applying the budgets to it and rewriting SPEC-058's promise was the rejected alternative. **The cost is accepted:** `json.dumps` stops at the first fault, so a result that faults early reaches the pass nearly unwalked. At `6c3837a` a `bytes` value ahead of a 16^6 shared sublist with leaf `[0]` spent about 10 µs in the check and about 8 s and 1.7 GiB in the coercion, where a budget would have stopped it at 131,072 values. With no fault the same shape cost about 1.2 s and 0.16 GiB, all in the check, which no budget reaches. A fault therefore multiplies the cost several times over, and the acceptance rests on the output being the caller's own code.

**A stop, not a placeholder per value.** The breach ends the walk. The shape `<depth limit>` has, a placeholder for every value past the line while containers keep iterating, was rejected because it still writes up to (`max_depth` + 1) × `max_keys` of them after the breach. The cost is stated: walk order decides what is sacrificed, the first `_MAX_NODES` values in walk order survive, and since the walk follows the merged mapping's insertion order (config defaults, span defaults, baggage, per-call fields) a default or a baggage value near either budget sacrifices the per-call fields after it. Every cut is marked. **Per pass, not per event**, because the counters live on the pass object that already existed to carry `truncated` out of deep recursion, so no module-level state is stranded across a fork (invariant 12); a pathological `configure(defaults=…)` is therefore walked, to the budget, on every event. **Private constants, not `configure()` keys:** a knob can be appended later and one that ships cannot be withdrawn (invariant 10; the worker tunables were deferred on the same ground in `public-api.md`). **A work budget, not a size limit:** a destination's hard limit is still met by lowering `max_value_bytes` or `max_keys`, and `dropped_oversized` still counts what a sink refuses. This reverses the deferral of a per-event byte ceiling by SPEC-017, SPEC-020 and SPEC-021, who left it for its design surface, what happens on breach and which fields are sacrificed first: the answers are a placeholder and a stop, and walk order. The number, the placeholder text, the stop and the counting are deliberately those of the record budget in SPEC-056's draft (branch `spec/056-otlp-log-export`), so the two stay equal; keeping them equal is that spec's to settle when it builds.

**What is charged.** Three classes. Text from the caller (a `str` value or key, text decoded from a bytes-like, an enum member's `str` value) is charged at its UTF-8 length *after* clipping, because it already exists and clipped costs the event at most the ceiling; charging it at its pre-clip length was rejected, since it turns today's clipped 20 MB string field into `<size limit>`. Text the pass produces by calling `str()` or `isoformat()` itself (a `Decimal`, a `UUID`, a date, a non-`str` key) is charged at the larger of its characters before clipping and its bytes after, because producing it was the work: one 10-million-digit `Decimal` referenced 256 times is 2.56 billion characters of `str()` that clipping afterwards does not undo. An integer written as a value is charged at the length `integer()` estimates, from the **unbound** `int.bit_length`; fixed placeholders, floats, bools and `None` are charged nothing and bounded by the node count. A produced text over the whole budget is replaced rather than clipped, the instinct of *A value too large to render*, so a `Decimal` of more than about 16.7 million digits changes from clipped to `<size limit>`. A mapping entry's key is rendered and charged **before** its value is visited, reversing the order Python evaluates a subscript assignment, so a key that crosses leaves its value unread; an integer key is priced at a lower bound of its length and not rendered when that already crosses.

**A read costs the ceiling, not the input's length** (SPEC-057 FR-003), or the budgets would be spent by reading rather than by writing. `truncate_str` reads the first `max_bytes + 1` characters and `truncate_tail` the last, through unbound `str.__len__` and `str.__getitem__`; one more than the ceiling because the clip fires when the encoding *exceeds* it. A `bytes` or `bytearray`, exact or a subclass, is read through the unbound slice of its own type and never through its buffer; a `memoryview` is read only once its exact type is confirmed, because `isinstance` consults `__class__` and an object that merely claims to be one is a type-name placeholder, and then as whole rows up to the cut. The rendering is byte-identical to the unbounded computation, flag included, and the tests hold it to a reference copy of the old algorithm rather than to the argument. One recorded exception, hostile-only: a `bytes` subclass overriding `__bytes__`, or a `bytearray` subclass overriding `__bytes__` or `__buffer__`, is rendered from the bytes it stores. **What the library measures about a value, the library computes:** an `int` subclass whose own `bit_length` returned `nan` made the running charge `nan` and switched the budget off for the rest of the pass, measured at `b282c1d`, which is why the estimate reads the unbound accessor.

**Rejected:** memoising by `id()` (the output must be a JSON tree, so a DAG's output is exponential anyway); a global visited set (two siblings referencing one object must both render); a `__sizeof__` gate for `Decimal` (on CPython it reports an allocation, not a digit count, so it gates falsely at a small `max_value_bytes`); a smaller node budget in place of the byte budget (2,048 nodes would bound the bytes, cut a 256 × 256 structure and diverge from SPEC-056); a `configure()` knob for either budget. **Not closed here, and recorded in `architecture.md` §12:** a mapping key built from a shared sub-structure is rendered whole before any budget applies, and several type-impostor routes let an object claiming to be a `bool` or `float` reach the event. The spec's Accepted Limits hold the rest. (SPEC-057)
