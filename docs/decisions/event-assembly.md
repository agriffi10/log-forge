# Event assembly: safety and bounds — decisions

cost. Read the fences; pull an entry only when you need the reasoning.

## Fences

- **A reserved word needs exactly one route through, including its own name** — `fields` is the third reserved word and `fields={"fields": …}` must work. The keyword form wins a collision, and the merge **absorbs** a non-mapping rather than raising. (SPEC-025, SPEC-034)
- **An event is safe by construction — coerced and bounded once at assembly, not per sink** — `build_event` runs every value through `sanitize.py`, so the bare `json.dumps` calls in `sinks/` are correct by consequence. The unserializable fallback is a type name, never `repr()`. Ceilings bound each *value*; each pass is bounded too. A surrogate becomes U+FFFD, marked; a hostile key costs only itself. A transform's output is the exception: it is coerced at the transform instead. (SPEC-017, SPEC-055, SPEC-057, SPEC-058)
- **A value too large to *render* is replaced, never clipped** — an over-long int becomes `<int: ~N digits>`; a truncated number is silently wrong. Detection is `bit_length()`, never `len(str(v))` — the obvious check raises the very error it prevents. (SPEC-020)
- **A transform's output is checked against invariant 8's observable and coerced for type only, never clipped** — each result of a `TransformSink` function passes `json.dumps(result, allow_nan=False, ensure_ascii=False).encode("utf-8")` as the same object, or is replaced by `sanitize._coerce_unbounded`: assembly's per-type rules under no configured ceiling and one fixed depth bound of 100, marked. Not loss, so nothing is counted. (SPEC-058)
- **Each coercion pass is bounded by a node and a byte budget** — except a transform's types-only coercion, which stays unclipped; a pass visits at most 131,072 values and charges at most 16 MiB of text; the value that crosses either becomes a marked `<node limit>` or `<size limit>` and the walk stops, so walk order decides what is sacrificed. Private constants, not `configure()` keys; a work bound on the caller's thread, not a size limit tuned to a sink. A read costs the ceiling, not the input's length. (SPEC-057)

### A reserved word needs exactly one route through, including its own name

**A reserved word needs exactly one route through, including its own name** — `echo` and `message` were parameters stealing ordinary words from the field namespace, and `fields=` is the escape hatch, so `fields` becomes the third reserved word and `fields={"fields": …}` must work. The keyword form wins a collision (`{**base, **overrides}`), and the merge **absorbs** a non-mapping rather than raising: it runs in the emitter, outside `api._log`'s orphan guard, so an unguarded merge broke SPEC-025's promise on all four paths. (SPEC-034 FR-004)


### An event is safe by construction — coerced and bounded once at assembly, not per sink

> **Extended by SPEC-058.** "Once, at assembly" holds for every event `build_event` builds, not for what a `TransformSink` returns: its function runs after assembly, so its result is checked and coerced for type only at the transform. Full entry: [A transform's output is checked against invariant 8's observable and coerced for type only, never clipped](#a-transforms-output-is-checked-against-invariant-8s-observable-and-coerced-for-type-only-never-clipped).

> **Narrowed by SPEC-057 (2026-10-19).** "Ceilings bound per *value*, not per event" is still true of
> the four ceilings, but it stopped being the whole of the promise: each coercion pass is now also
> bounded as a whole, at 131,072 values visited and 16 MiB of text charged. Those budgets bound the
> work on the caller's thread and not the event's size at any destination. The full entry is "Each
> coercion pass is bounded by a node and a byte budget", below.

**An event is safe by construction — coerced and bounded once at assembly, not per sink** — `build_event` runs every value through `sanitize.py`, so all 40+ bare `json.dumps` calls in `sinks/` are correct by consequence, it costs one pass per event rather than one per destination (`MultiSink`), and the guarantee reaches the non-JSON sinks too. The unserializable fallback is a type-name placeholder, never `repr()`, so the fix cannot widen the PII exposure arch §6 prevents. The four ceilings bound each *value*, not the event's size at a destination; SPEC-057 bounds the pass itself. (SPEC-017, SPEC-057) **No string leaves assembly that cannot encode, and a stamp that cannot is refused at `configure()`** (SPEC-055 FR-001, FR-004): the clippers return an exact `str` — measured through `str.__str__`, so a subclass's `encode` or `__str__` cannot divert it — with every lone surrogate replaced by U+FFFD and `truncated` set, on the rule `real()` applies to a non-finite float: a substitution nobody can see is a silent change to the data. One U+FFFD per surrogate, because `errors="replace"` on encode writes `?` and a `surrogatepass` round trip writes three. Undecodable `bytes` are marked the same way. The three config stamps bypass assembly on purpose (the hottest path), so `configure()` refuses a non-`str` or non-UTF-8 stamp before the ownership stamp and stores `str.__str__` of it; an over-long stamp is recorded on `invariants.md` §8 rather than clipped. A mapping key whose rendering raises is confined to its own marked `<unserializable key: T>` placeholder — the guard is in `key()`, not in `mapping()`'s loop, whose other two failures already have owners — and two hostile keys of one type colliding on one placeholder is accepted over a numbered placeholder, the first step toward one carrying the key's identity. Both placeholders go through `text()`, since `type.__name__` is writable.


### A value too large to *render* is replaced, never clipped

**A value too large to *render* is replaced, never clipped** — `int` is the one type with no natural ceiling, and CPython refuses to render one past `sys.get_int_max_str_digits()`, so an over-long integer becomes `<int: ~N digits>`. Truncating digits would silently change the number, and a wrong number is worse than a visibly elided one. Detection is `bit_length()`, never `len(str(v))` — the obvious check raises the very error being prevented — with the ratio rounded so it errs toward replacing. (SPEC-020)


### A transform's output is checked against invariant 8's observable and coerced for type only, never clipped

**A transform's output is checked against invariant 8's observable and coerced for type only, never clipped** — `TransformSink` runs its function after assembly, so it can put `bytes`, a `datetime` or a NaN into an event that invariant 8 promised any sink could `json.dumps` bare, and 25 files under `sinks/` do. At `324936e`, Probe A (a transform in front of `LokiSink`) abandoned a 30-event batch and delivered 63 of 93 events, and Probe B (in front of `StdoutSink`) wrote 64 lines for 16 distinct events, each four times: the sink wrote the events ahead of the bad one, raised, and the worker retried the batch. So each result is checked once with `json.dumps(result, allow_nan=False, ensure_ascii=False).encode("utf-8")` — the stricter reading on purpose, because a NaN and a lone surrogate both pass a bare `json.dumps`. A result that passes is forwarded as the **same object**; one that fails, with any `Exception` (`RecursionError` included), becomes `sanitize._coerce_unbounded`'s output: assembly's own per-type rules (`bytes` decoded, `datetime` to ISO, `Decimal` and `UUID` to text, a non-finite float to its marker, a lone surrogate to U+FFFD, a cycle to its marker, anything else to the type-name placeholder), with `truncated` set exactly where assembly sets it. It is not loss, so nothing is counted or announced. **Check first**, so a valid result is untouched by construction and only a failure ever meets the coercer.

**Types-only, because `sanitize_fields` over a whole event is wrong:** it pushes `fields` one level deeper, so `max_depth` cuts a level early, and it clips a long `error.stack` string to `max_value_bytes` rather than `max_stack_bytes`. The coercion runs the same `_Coercer` under a stand-in config with its ceilings lifted — not a `Config`, which validates them. **One fixed depth bound of 100, because no bound is worse:** an unbounded pass over a 20,000-deep nest stopped at depth 331 on the main thread and 328 on another, with `<unserializable: dict>` and `truncated` false, a stack-dependent clip no reader can tell from the caller's data. So the pass has one private constant depth of 100, the same on every thread, past which a value is `<depth limit>` and `truncated: True`; a caller who sets `max_depth` above 99 and whose transform output fails the check gets it cut at 100, marked. **No top-level guard, unlike `sanitize_fields`:** a mapping the pass cannot enter propagates its exception to the wrapper's per-event guard, because an empty event delivered in place of a hostile one is a silent change to the data.

The ceilings do not bound what a transform adds — that is the caller's code choosing the size — and invariant 8 records it as an exception; re-applying them was rejected. **A limit the check introduced is recorded, not fixed:** it puts a `json.dumps` in front of inner sinks that never serialized (`MemorySink`, `CallbackSink`, `LoggingSink`), and a transform output nested deeper than the C stack allows can kill the process on a thread whose stack the caller set small (SIGBUS at 1 MiB on 3.13.1, macOS; Linux unmeasured). The same output already crashes every JSON sink's own `json.dumps` and only a transform can produce one, so it is a Known Constraint in `architecture.md` §13, not a guard. A peer spec (SPEC-057) adds per-pass node and byte budgets to the same coercer; neither relies on the other and whichever lands second rebases.

**Do NOT** coerce at each sink (25 files, one pass per destination under `MultiSink`); do NOT run `sanitize_fields` over the event; do NOT let a coercion count or announce. (SPEC-058 FR-001)

### Each coercion pass is bounded by a node and a byte budget

**Each coercion pass is bounded by a node and a byte budget** — `build_event` runs on the caller's thread on both delivery paths, and the pass bounded how deep, how wide and how long a *value* may be but not its own total work. A shared sublist is a DAG, not a cycle, so the ancestor check never fires on `y = [y] * 16` applied seven times and the pass made 16^7 visits; the same walk over an 8 KiB string shared across every one of 131,072 values is a gigabyte of event. So a pass visits at most **131,072 values** (`sanitize._MAX_NODES`) and charges at most **16 MiB** of text (`sanitize._MAX_RENDERED_BYTES`); the value that would cross either becomes `<node limit>` or `<size limit>`, `truncated` is set, nothing after it is visited, and every open container ends after the member it was writing. (SPEC-057 FR-001, FR-002) **The numbers:** 131,072 is twice a fully populated two-level structure at the default `max_keys` (256 × 256), so a wide but ordinary event is not cut, and no larger, so the worst pass stays small; 16 MiB is far above any sink here (SQS takes 256 KB), and reaching it legitimately takes at least 2,048 full strings at the default 8 KiB ceiling, so in practice it only catches amplification. `json.dumps` escapes a control character as six bytes, so the serialised worst case is about six times the byte budget per pass, and a boundary event takes two passes, `build_event`'s and `backfill_baggage`'s.

A transform's coercion is outside both budgets (`_Coercer(budgeted=False)`). SPEC-058's types-only pass promises not to clip, and with the budgets in it a 20 MiB string became `<size limit>` and every later key, envelope keys included, was dropped, with every test green. Its check has already walked the output with `json.dumps`, so a budget there would bound little. Applying the budgets to it and rewriting SPEC-058's promise was the rejected alternative.

**A stop, not a placeholder per value.** The breach ends the walk. The shape `<depth limit>` has, a placeholder for every value past the line while containers keep iterating, was rejected because it still writes up to (`max_depth` + 1) × `max_keys` of them after the breach. The cost is stated: walk order decides what is sacrificed, the first `_MAX_NODES` values in walk order survive, and since the walk follows the merged mapping's insertion order (config defaults, span defaults, baggage, per-call fields) a default or a baggage value near either budget sacrifices the per-call fields after it. Every cut is marked. **Per pass, not per event**, because the counters live on the pass object that already existed to carry `truncated` out of deep recursion, so no module-level state is stranded across a fork (invariant 12); a pathological `configure(defaults=…)` is therefore walked, to the budget, on every event. **Private constants, not `configure()` keys:** a knob can be appended later and one that ships cannot be withdrawn (invariant 10; the worker tunables were deferred on the same ground in `public-api.md`). **A work budget, not a size limit:** a destination's hard limit is still met by lowering `max_value_bytes` or `max_keys`, and `dropped_oversized` still counts what a sink refuses. This reverses the deferral of a per-event byte ceiling by SPEC-017, SPEC-020 and SPEC-021, who left it for its design surface, what happens on breach and which fields are sacrificed first: the answers are a placeholder and a stop, and walk order. The number, the placeholder text, the stop and the counting are deliberately those of the record budget in SPEC-056's draft (branch `spec/056-otlp-log-export`), so the two stay equal; keeping them equal is that spec's to settle when it builds.

**What is charged.** Three classes. Text from the caller (a `str` value or key, text decoded from a bytes-like, an enum member's `str` value) is charged at its UTF-8 length *after* clipping, because it already exists and clipped costs the event at most the ceiling; charging it at its pre-clip length was rejected, since it turns today's clipped 20 MB string field into `<size limit>`. Text the pass produces by calling `str()` or `isoformat()` itself (a `Decimal`, a `UUID`, a date, a non-`str` key) is charged at the larger of its characters before clipping and its bytes after, because producing it was the work: one 10-million-digit `Decimal` referenced 256 times is 2.56 billion characters of `str()` that clipping afterwards does not undo. An integer written as a value is charged at the length `integer()` estimates, from the **unbound** `int.bit_length`; fixed placeholders, floats, bools and `None` are charged nothing and bounded by the node count. A produced text over the whole budget is replaced rather than clipped, the instinct of the fence below, so a `Decimal` of more than about 16.7 million digits changes from clipped to `<size limit>`. A mapping entry's key is rendered and charged **before** its value is visited, reversing the order Python evaluates a subscript assignment, so a key that crosses leaves its value unread; an integer key is priced at a lower bound of its length and not rendered when that already crosses.

**A read costs the ceiling, not the input's length** (SPEC-057 FR-003), or the budgets would be spent by reading rather than by writing. `truncate_str` reads the first `max_bytes + 1` characters and `truncate_tail` the last, through unbound `str.__len__` and `str.__getitem__`; one more than the ceiling because the clip fires when the encoding *exceeds* it. A `bytes` or `bytearray`, exact or a subclass, is read through the unbound slice of its own type and never through its buffer; a `memoryview` is read only once its exact type is confirmed, because `isinstance` consults `__class__` and an object that merely claims to be one is a type-name placeholder, and then as whole rows up to the cut. The rendering is byte-identical to the unbounded computation, flag included, and the tests hold it to a reference copy of the old algorithm rather than to the argument. One recorded exception, hostile-only: a `bytes` subclass overriding `__bytes__`, or a `bytearray` subclass overriding `__bytes__` or `__buffer__`, is rendered from the bytes it stores. **What the library measures about a value, the library computes:** an `int` subclass whose own `bit_length` returned `nan` made the running charge `nan` and switched the budget off for the rest of the pass, measured at `b282c1d`, which is why the estimate reads the unbound accessor.

**Rejected:** memoising by `id()` (the output must be a JSON tree, so a DAG's output is exponential anyway); a global visited set (two siblings referencing one object must both render); a `__sizeof__` gate for `Decimal` (on CPython it reports an allocation, not a digit count, so it gates falsely at a small `max_value_bytes`); a smaller node budget in place of the byte budget (2,048 nodes would bound the bytes, cut a 256 × 256 structure and diverge from SPEC-056); a `configure()` knob for either budget. **Not closed here, and recorded in `architecture.md` §12:** a mapping key built from a shared sub-structure is rendered whole before any budget applies, and several type-impostor routes let an object claiming to be a `bool` or `float` reach the event. The spec's Accepted Limits hold the rest. (SPEC-057)
