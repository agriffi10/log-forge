**A `dropped` count is written only by a `Deferral` commit, and the gate derives which counters are counted** — SPEC-058 applied its rule at five sites and named the rest as a follow-up; SPEC-059 applies it at every site, so a per-event drop at a shipped sink counts only when the `emit` that decided it returns. Measured at `33a0cd3`, through the real `Worker` with `max_retries=3`: one oversized event read `dropped_oversized == 4` in seven sinks (`SyslogSink`, `LogstashSink`, `KinesisSink`, `FirehoseSink`, `SNSSink`, `MongoDBSink`, `AzureEventHubsSink`) and in `HTTPSink._drop_refused`; three refusals read `rejected == 12` in `KafkaSink` and `GooglePubSubSink`, and read 3 when every hand-off was refused once and then accepted, a loss that never happened; and one refused event on the orphan path sat in `dropped` and in `orphan_lost` at once, which invariant 2 forbids. The five record-building sinks take the calling `emit`'s `Deferral` (Event Hubs outside its `_lock`, so its oversize line is no longer written under it); Kafka and Pub/Sub enclose the produce/publish loop, `_reap()` and the total-failure raise, so a batch refused whole raises and counts nothing — the catcher owns it — while a partial refusal commits, each line naming its own exception type, bound when the refusal was decided. Under `MultiSink` the oversized or refused event of a child that raises moves from `dropped` to the fan-out's absorbed `failed`. SPEC-069 added one more drop to the same commit, an event the sink cannot encode: it lands in each sink's private `_unencodable`, in `rejected` for Kafka and Pub/Sub, and in `SocketTransport._unencodable` for the two socket sinks, entered through the same ledger, so `dropped_oversized` still means oversize only.

**The socket transport's ledger is entered in the calling sink's `emit`** (`Deferral(self._socket)` in `SyslogSink` and in `LogstashSink`'s socket branch) and passed to `SocketTransport.send_all` and `_sendable` as a **required** parameter, so the commit sits at the boundary the worker actually retries and mypy, and a `TypeError`, refuse a caller that forgets it. Rejected: a `Deferral` inside `send_all`, which needs the gate's construction rule (a `Deferral` only as a `with` item in an `emit`) widened to a second entry name, and makes the commit depend on `send_all` being the last statement of every caller.

**The gate derives the counters instead of listing them.** `tests/test_deferral.py` reads every `SinkLosses(dropped=…)` and `wrapped_losses(own=…)` call in `src/` — the callee spelt bare or as an attribute, the argument by keyword or position, in any function and not only `losses` — and takes the `self.<attr>` names in it: one hop through a local assigned in the same function (never transitively, which would derive `MultiSink._sinks`), and the last name of a read chain. A store to any of them anywhere but `__init__`'s own statements (a closure defined there runs after construction and is scanned), in any class under `src/`, is a finding, matched by name across the tree and at any position of a stored path (`self._socket.dropped_oversized += 1` is caught); a `setattr(self, …)` with a computed name is a finding too. Every rule fails closed. A pinned floor of six names (`dropped_oversized`, `_unrenderable`, `_id_failed`, `rejected`, `_dropped`, and SPEC-069's `_unencodable`) makes a refactor that blinds the derivation redden instead of shrinking the guard. It reads syntax, so an alias of `self`, a mutating method call and a counter reported through a call or a property are not seen, which its docstring says.

**No allowlist.** A `dropped` count is exact by promise (invariant 2), so a store that has to be immediate belongs to a counter that is not reported as `dropped`, and breaking the promise should mean editing the gate, deliberately. Rejected: an allowlist like `IMMEDIATE`, which would have made the exception a one-line edit. Accepted costs: an unrelated class storing a same-named attribute outside `__init__` is a finding and renames it, and a Pub/Sub refusal line can trail its refusal by up to one reap wait, which `overflow_timeout` bounds.

**Do NOT** add an allowlist to the derived check; do NOT count a `dropped` attribute anywhere but in a `Deferral` commit; do NOT give `send_all` or `_sendable` a default ledger, which lets a caller count at once by omission; do NOT recount `failed`, an upper bound by design. `NullSink.dropped` and `SentrySink.skipped` are not reported as `dropped` and are not this decision. (SPEC-059 FR-002, FR-005)
