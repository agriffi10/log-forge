---
type: Decision
title: "A sink's own driver error is counted, announced and raised as both types"
description: "When `SQLiteSink`'s insert raises `sqlite3.Error`, or a `FileSink` or `RotatingFileSink` write or flush raises `OSError`, the sink adds the batch to a private `_failed` at once, writes one line naming the class and type (and `errno=N`), and raises an instance of both `SinkDeliveryError` and the driver's own class, built by `sinks/_driver_error.delivery_error`, which has no public name. (SPEC-069)"
---

**Counted, announced, then raised.** `SQLiteSink.emit` let `sqlite3.Error` escape and the two file sinks let `OSError` escape (`OSError(28)` from a full disk was measured), with no `losses()` to report it and no line of their own; only the worker's abandon line, after its retries, said anything. Each now does what every counting sink does: under its own `_counter_lock`, never the emit lock, so a `losses()` poll does not wait behind a write (SPEC-028 FR-003), it adds `len(batch)` to a private `_failed`, reported as `losses().failed`; it writes one `_diag.lost` line, `<Sink>, <Type>`, with `errno=N` for an `OSError`; and it raises. The count lands before the raise and again on each worker retry of the batch — the recorded upper bound of invariant 2 — and `tests/test_deferral.py`'s `IMMEDIATE` names the store. An event the same call dropped as unencodable is discarded with the raise, as any per-event drop is, and so sits in the `len(batch)` the call counted. A closed sink still raises a plain `SinkDeliveryError` and counts nothing.

**Raised as both types, so no `except` clause changes.** Callers wrote `except sqlite3.Error`, `except OSError` and `except PermissionError` around these sinks; the library's word for "this sink delivered none of the batch" is `SinkDeliveryError`. `delivery_error` derives, once per original class and cached, a class whose bases are `SinkDeliveryError` and the original's own class, and builds the instance from the original's `args`. It copies only the attributes the original actually set that `args` does not carry — `filename` and `filename2` when not `None`, and the `sqlite_errorcode` and `sqlite_errorname` the driver stores on the instance — because copying an unset one corrupts `str()` (`filename2=None` renders `... 'f' -> None`; a plain `OSError("plain")` renders `[Errno None] None: None -> None`). The class keeps the original's `__name__`, `__module__` and `__qualname__`, so the worker's abandon line reads as it did in 1.1.0; the original is the `__cause__`; and `__reduce__` rebuilds the original class from its `args` and copied attributes, so a pickled instance unpickles as the driver's own exception — without it every instance fails to pickle, since the class is built at run time. If the class cannot be built (a constructor that rejects its own `args`, bases that cannot share a layout), the sink raises the original unchanged, still counted and announced, because the library never fails the caller on its own fault (invariant 1).

**Not public surface.** A frozen name is inherited and kept for all of `1.x` (*A protocol that is exported is a protocol that will be inherited*), and nothing needs one: `isinstance(exc, SinkDeliveryError)` and the driver's own `except` already match. The derived class is in no `__all__` and has no documented import path; `SinkDeliveryError`'s docstring says a sink may raise such a subclass. Rejected: a static subclass per driver type, which cannot cover a type the driver adds and is not the driver's class for an `except` written against a narrower one. Accepted: this is dynamic inheritance and module state, which the Python rulebook asks to avoid (§15, §13), and `_driver_error.py`'s docstring says so.

**A partial write's duplicates are an accepted edge for 1.2.0** (Andrew's ruling, 2026-11-13). A `FileSink` or `RotatingFileSink` write that fails partway leaves the earlier lines of the batch on disk, the sink raises, and the worker's retry writes the whole batch again; a `StdoutSink` or `StderrSink` stream that raises partway does the same. Measured with `RLIMIT_FSIZE` capping the file partway through a 200-event batch and lifted before the second `emit`: 69 to 100 of the 200 events landed twice, and no line was torn, because CPython's `BufferedWriter` keeps the unwritten tail in its buffer and the next flush finishes it. A fault that persists fails the retry too and duplicates nothing, so the duplicates need the fault to clear between attempts. This is a recorded exception to invariant 7's "no event landed twice". Two remedies are rejected. Truncating the file back to where the batch began would delete the lines a forked child appended to the same file in between (invariant 12). Flushing per line and reporting a partial write instead of raising trades the duplicates for losing the unwritten rest, which is never retried even when the disk recovers, and made a 1,000-event batch about eleven times slower to write (0.17 ms against 1.89 ms). The closure is moving the file sinks onto `deliver`, so the engine resends only what did not land, as its own spec after 1.2.0.

**Do NOT** make a partial file write atomic under this decision, by truncation or otherwise; do NOT export the derived class; do NOT copy an attribute the original did not set; do NOT take the emit lock to count. (SPEC-069 FR-004)
