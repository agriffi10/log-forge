---
type: Decision
title: "A bad argument is floored if it works and refused if it is already broken; a new one is refused"
description: "an unusable timeout, a CRLF header or token, a non-`http` URL, a non-positive chunk size or interval, a bad DSN and an argument the chosen backend cannot use raise at construction; `max_bytes<0`, `overflow_timeout=inf` and the `usable_timeout` callers floor, since those deliver. (SPEC-049)"
---

**A bad argument is floored if it works and refused if it is already broken; a new one is refused** — one rule for every degenerate constructor argument in the sink family, stated once (SPEC-049 FR-001) and applied across four FRs. The library already *floored* `max_retries` at zero, `max_batch_count` at one, libpq's `connect_timeout` at two, and `KafkaSink`/`NATSSink`'s timeouts back to their module defaults through `_retry.usable_timeout`; every one of those lands on a configuration that delivers, so flooring is a no-op for a sane caller and a silent rescue for the rest. Every *refusal* SPEC-049 added is on a value that, measured at `212fd16`, either destroyed data silently or raised an uncounted exception on every batch for the life of the process: `HTTPSink(timeout=-1)` raised a raw `ValueError` out of every `emit`; `ClickHouseSink(chunk_size=-5)` returned normally having inserted nothing; `RotatingFileSink(interval=0)` left two of fifteen lines on disk; CR/LF in a header or bearer token, a `file://` URL, a Sentry DSN with no host, a whitespace `app_name` or index name, and an argument the selected backend cannot consume (`LogstashSink(url=…, host=…)` and the reverse, `NATSSink(client=X, servers=…)`, a non-positive `max_reconnect_attempts`) all fail later or never. Those raise `ValueError` at the constructor, naming the argument and the value, through `_retry.require_timeout`/`require_positive` — raising siblings of `usable_timeout` sharing its `NaN`-safe `not (0 < v < inf)` test. **The floor side is protected, not merely tolerated:** `RotatingFileSink(max_bytes=-1)` and `(backup_count=-1)` behave identically to the documented `0` and are floored to it, and `GooglePubSubSink(overflow_timeout=inf)` *delivers* against a healthy client, so it became the third `usable_timeout` caller rather than a refusal — refusing `inf` there while flooring it for Kafka would have been two rules for one value; the spec's first draft refused both and its reviews caught each. **A newly added argument is refused** (the FR-005 driver bounds: `MongoDBSink`'s `socket_timeout` and `server_selection_timeout`, `RabbitMQSink`'s `blocked_connection_timeout`, `socket_timeout` and `stack_timeout`, `ClickHouseSink`'s `send_receive_timeout`) because it has no working configuration to protect, and is refused beside an injected client, which cannot consume it (SPEC-043). **Precedence for a bound the caller may also have written into a URI:** the library default applies only when the URI names nothing; an explicit keyword overrides the URI; the default never does — pika's model, and deliberately not `PostgresSink`'s DSN override, because pika and pymongo let the two be told apart where libpq did not. **Found by sweeping, not by reading:** the system-frame diff review enumerated every numeric constructor argument in `sinks/` and ran each degenerate value, and the rule had been left unapplied on `PostgresSink`'s chunk loop, `SocketTransport`'s `port` and `max_datagram_bytes`, `HTTPSink`'s `max_batch_bytes` (a floor at `1` that delivered nothing — a floor must land on a value that *delivers*, or it is a refusal wearing a floor's clothes) and `body_format`, and three `maxlen`s; a spec that applies a rule to the sites it noticed owes a sweep of the sites it did not. **Do NOT** convert the floor-side callers into refusals for consistency's sake — that is a breaking change at 1.0 for a configuration that works, and the pins in `tests/test_sink_retry.py` and `tests/test_sinks_pubsub.py` exist to fail such a change; do NOT floor a new argument, which would hide the caller's mistake behind a default they never chose; do NOT validate a value the selected backend never reads (`SentrySink(backend="sdk")` never parses the DSN) — refusing it would invent a failure rather than report one. (SPEC-049)
