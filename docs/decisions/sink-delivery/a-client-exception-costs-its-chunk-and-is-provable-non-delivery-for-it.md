title: "A client exception costs its chunk, and is provable non-delivery for it"
description: "guarded *inside* `_send`, since an outer guard reports a partial success as \"nothing delivered\"; it makes the chunk `RETRYABLE` (SPEC-074; it fed the SQS and SNS recoverable term), or a total failure returns silently. Only an exception the sink's predicate accepts is retried inside `_send`; any other costs its chunk at the first attempt. (SPEC-048, SPEC-070)"
---

**A client exception costs its chunk, and is provable non-delivery for it** — the four AWS batch sinks called their client unguarded inside a chunk loop, so a `ClientError` on chunk N escaped `emit` after chunks 1..N-1 had landed, and the worker retries *whole batches*: measured `duplicates=10` for a 25-event SQS batch and `duplicates=500` for 1,000 Kinesis records, `losses()` reading `(0, 0)` throughout. The exit drain is one large batch by construction, so it is exactly this shape. **The guard goes inside `_send`, never around it in `emit`**: by the time `_send` raises it may hold a non-zero `accepted` from an earlier attempt and have narrowed its entries to the retryable subset, so an outer guard charges the whole chunk and reports a partial success as "nothing delivered" — provoking the very retry it was added to remove. **Treated as provable non-delivery**, which ~~feeds `SQSSink`'s `recoverable_loss` term~~ (superseded by SPEC-074: makes the chunk `RETRYABLE`, and a run in which nothing landed still fails) so a wholly-failed batch still raises; without that the guard converts a total failure into a silent one, which is SPEC-026's defect reintroduced by its own fix. The cost is real and recorded rather than argued away: a read timeout means the request went out and the *reply* was lost, so a re-send may duplicate — SPEC-018's "cannot prove nothing landed". It is taken on expected cost, because an unreachable endpoint is the common client exception and is precisely what the worker's retry exists for, while suppressing the raise for it would lose every event of every batch for a whole outage; `boto3`'s own `max_attempts` already carries the duplication property. `KinesisSink`/`FirehoseSink`'s `unknown` term is **not** set by the guard: SPEC-018's "unadjudicable" describes a *response*, and an exception is not a response. The roster that keeps this true is derived on **shape** — every `_send` calling `self.client.<method>(...)` — with a floor, because a hard-coded four-module list leaves a fifth AWS-shaped sink green. (SPEC-048 FR-002) **Only a transient exception is retried inside `_send`** (SPEC-070 FR-001, FR-002): the guard still catches `Exception`, but it retries only what `aws_retryable` accepts — botocore's connection errors and a `ClientError` whose status or code is transient or a throttle — and anything else, a `ParamValidationError` or a `TypeError` from the caller's own client, costs its chunk at its first attempt, counted and announced with `1 attempt(s)`. It is still provable non-delivery for that chunk, so it still feeds the recoverable term; `SNSSink._send` now returns that term as `SQSSink._send` does, `(accepted, recoverable loss)` (superseded by SPEC-074: the recoverable term is gone, and such a chunk is `REJECTED`) (*A sink declares what it retries, and anything else fails at once*).

## History

### 2026-11-09

- **Restated** by SPEC-074 FR-002 for the engine sinks: the exception makes its chunk `RETRYABLE`, which the engine resends within the run's budget, where it used to feed the SQS and SNS recoverable term and the sink's own loop; one the predicate refuses is `REJECTED` at its first attempt. The guard still sits around the client call inside `_send`.

### 2026-11-07

- **Applied to `deliver`** by SPEC-072 FR-004, fence unchanged: an exception escaping `deliver` is not a response, so the engine fails its round's events — counted in `failed_events`, toward a failed run that moves `failed_batches` or `orphan_lost` — and announces the exception's type, never its text. The retry half lives inside a sink's `deliver`, which catches its client's exception and returns `RETRYABLE`; the engine itself resends an escaped exception only for a sink declaring `log_foundry_idempotent = True` whose `_retryable_error`, bound and asked through `is_retryable`, accepts it. The inline adapter's raise for such a run invites the catcher's whole-batch retry, the expected-cost trade this entry records.
- **Refined** by SPEC-070: the guard retries only a predicate-accepted exception and counts any other at its first attempt; `SNSSink._send` returns the recoverable term too.

### 2026-09-02

- **Settled.**
