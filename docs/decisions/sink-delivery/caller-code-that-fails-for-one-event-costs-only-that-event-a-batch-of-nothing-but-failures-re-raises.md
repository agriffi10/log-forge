**Caller code that fails for one event costs only that event; a batch of nothing but failures re-raises** — four pieces of code run once per event in front of a sink: `TransformSink`'s function, `FilteringSink`'s predicate, `SQSSink`'s FIFO `message_group_id` and `message_deduplication_id` callables, and `HTTPSink._items`' `_render` and `_item_size`. Each used to cost the whole batch when it raised for one event — the siblings were never forwarded and the abandon line reported them lost — and each now drops that event alone, under a guard that catches `Exception` and never `BaseException`. **The ledger rule:** if every event failed (at least one, nothing forwarded, nothing deliberately dropped by a `None`, a `False` or the level floor) the first exception is re-raised unchanged and nothing is counted, which is the old behaviour byte for byte — the catcher above owns the batch, and for the orphan path's one-event batch an event whose callable fails *is* the whole batch, so `orphan_lost` counts it once where a wrapper count as well would count it twice. Otherwise the rest is forwarded; if the inner `emit` raises nothing is counted (*A raising `emit` counts nothing*); once it returned, the failures are counted in the wrapper's private count and announced once per batch through `_diag.lost`, naming the class and the first exception's **type**, never its value (invariant 11). A `TransformSink` result that is neither `None` nor a `dict` is the same failure, as a `TypeError` the wrapper builds naming its class and the type returned; the predicate still runs before the level floor. The accepted cost: an event whose callable failed transiently is lost without a retry when its siblings succeeded, because retrying the batch re-delivers the siblings, and a duplicate breaks invariant 2 worse than one counted loss.

**Each wrapper reports its own count.** `losses()` is `None` only when the inner sink reports `None` *and* the wrapper's own count is zero, else `SinkLosses(dropped=inner.dropped + own, failed=inner.failed)` — `MultiSink`'s rule for a child that reports nothing — through a private count under `_counter_lock` (not `_lock`, which the transport-lock lint reads as a transport lock); no public name was added. `SQSSink` and `HTTPSink` fold a private `_id_failed` and `_unrenderable` into `losses().dropped`, and `dropped_oversized` keeps meaning oversize only; `ElasticsearchSink.losses()` overrides the base and reads `dropped_oversized` directly, so it needed the fold-in too.

**A sink's own encode is deliberately not the same rule** — first the HTTP half, and since SPEC-069 every record-building sink. A batch in which every event is unrenderable or oversized settles without raising, counted and announced, because re-encoding identical input in the sink's own code fails identically and a retry cannot help, where a caller's callable can fail differently on the next attempt. SPEC-069 wrote that rule once, as `sinks/_encode.encode_events`, and put every other record-building sink on it: an event the sink cannot encode is dropped alone, counted `dropped`, and a batch of nothing encodable settles — the entry [An event a sink cannot encode costs only itself](an-event-a-sink-cannot-encode-costs-only-itself-and-a-batch-of-nothing-encodable-settles-counted.md) carries the reasoning and its two declared exceptions, `NATSSink` and `SentrySink`. HTTP's guard is also the backstop for an unverified report that CPython on Windows raises `OSError` from a naive pre-1970 `datetime.timestamp()`, which `sinks/_time.py` does not catch; nobody here could run Windows, so `_time.py` is unchanged and the cost, if the report is real, is bounded to the one event.

**Do NOT** count a failure when the inner `emit` raised; do NOT re-raise for a partial failure, which re-delivers what landed; do NOT apply the all-failed re-raise to an event the sink's own encode refuses, HTTP's unrenderable events or any record-building sink's (SPEC-069); `CallbackSink` is not this decision — its function runs once per batch and is the terminal destination. (SPEC-058 FR-002, FR-003, FR-004, FR-005)

## History

### 2026-11-09

- **Applied on the engine to the wrappers**, by SPEC-075 FR-002: a `FilteringSink` or `TransformSink` that offers `deliver` (its inner sink does) follows the same rule when its predicate or transform fails on every event of a call. The events are `REJECTED` with the refusal marker (`refuse(first_exc)`), so the batch costs one attempt and is **no longer retried by the worker**. No sink counter moves (the shared `failed_events`, the inner sink's `losses()` and the wrapper's `_dropped` are unchanged), the catcher's `failed_batches` or `orphan_lost` counts it, and `emit` re-raises the first exception by identity. A partial failure is `SKIPPED` and counted in the wrapper's `_dropped`, `SETTLED`, announced by a per-call `absorbed a failure` line rather than the `emit` path's `lost` line. Caller code runs once per event per engine run, because both wrappers forward a resend from the run's notes without asking the predicate or function again, so a failure, and the all-failed refusal, arise only in the round that first sees an event, never on a resend (the predicate half settled from the frame-2 review, Andrew's call). A wrapper over an emit-only sink keeps the 1.x re-raise and the worker's retry of it. The fence's "re-raised unchanged and nothing is counted" stands.
- **Applied on the engine, `SQSSink` FIFO only**, by SPEC-074 FR-001: when every event's id callable raised, the events are `REJECTED` with the refusal marker (`refuse(first_exc)`), so the batch costs one attempt and is **no longer retried by the worker**; no sink counter moves, the catcher's `failed_batches` or `orphan_lost` counts it, and `emit` re-raises the first exception by identity. The fence's "re-raised unchanged and nothing is counted" stands. The wrappers' half is SPEC-075's to record (above).

### 2026-11-06

- **Widened** by SPEC-069 FR-001, FR-002: the HTTP half's settle-don't-re-raise rule now covers every record-building sink's encode step, through one helper.

### 2026-10-22
