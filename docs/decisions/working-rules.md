## Fences

- **A subclass that inherits a method is still in the roster** — scope a roster on defines-or-inherits: keying on *defining* a method made membership a function of where code sits, and dropped five classes out of two lints in one commit with the suite green. (SPEC-038)
- **A bound is only a bound if it is measured where it binds** — assert **CPU** time, not wall clock, or a busy-spin passes; a timeout applied per *item* is `n × timeout`, not a bound. (SPEC-038)
- **An open item is closed by being fixed, settled, or recorded as a constraint — never deleted** — a note merely removed takes its reasoning with it, and a reader cannot tell a live defect from a decision that reads like one. Supersede in place, struck through and marked with the spec that closed it. (SPEC-021)
- **A rule with no gate is a rule that rots, and the cap that rots is the one contradicted by its neighbour** — the ≤3-sentence docstring cap sat beside "reasoning ... belongs *in* the docstring" and the code followed the neighbour, a third of defs over it. Re-scoped to the **summary line**, where compliance was already total, so `scripts/docstring-lint.py` shipped green. Its corpus mutation-tests every **exemption**, not just every check. (SPEC-052)
- **A read-only finding is not closed until it has been run, and the job that runs it needs a floor rather than an exit code** — fourteen sink modules reach a third party through eleven optional extras and none was ever executed, so the sinks most likely to be in production were the least verified. **A floor, not an exit code:** a fixture that skips on an absent service exits **0**, so a dropped module reads as a smaller pass count and nothing fails — an absent service must fail, and a per-module floor makes a silent shrink loud. (SPEC-041)
- **The supported-Python versions have one authority — the CI matrix — and restatements are bound to it, not to each other** — the matrix is the only site that is *evidence* rather than a claim; a *set* claim must equal it, a *floor* claim its minimum, and the boundary is the LINE, not the file. What it does **not** establish — that the matrix was *triggered*, or that a line outside the swept files agrees — is recorded, not chased with a further check. (No spec — PR #200)

### A subclass that inherits a method is still in the roster

**A subclass that inherits a method is still in the roster** — scope keyed on *defining* one makes membership a function of where code happens to sit, and moving five `emit`s into a base dropped those classes out of two lints in a single commit, 34 → 29, with the suite green. Only the sibling roster noticed, and only because it had a floor guard. Both rosters now scope on defines-or-inherits, both carry floors, a class overriding neither `emit` nor `close` may answer from the ancestor whose code it runs, and **a test asserts the two cover the same classes** — they had already drifted twice on trigger and on base spelling. (SPEC-038 FR-001 AC-1a/AC-1b)


### A bound is only a bound if it is measured where it binds

**A bound is only a bound if it is measured where it binds** — the recurring shape behind five of this spec's seven blocking defects. A wall-clock assertion cannot see a busy-spin (a slice loop bounded at 1.00 s wall burned 3.5 M calls and a pegged core, so the test asserts **CPU** time); a timeout applied per *item* is `n × timeout`, not a bound; and a chunk size is a floor division, so a byte-charging test only bites at sizes where the division tips — the same test was vacuous at 1,012 bytes (the count limit binds first) and again at 9,000, and now asserts its own sensitivity as a precondition. (SPEC-038 FR-004, FR-005)


### An open item is closed by being fixed, settled, or recorded as a constraint — never deleted

**An open item is closed by being fixed, settled, or recorded as a constraint — never deleted** — a note that is merely removed takes its reasoning with it, and a reader cannot tell a live defect from a decision that reads like one. Superseded notes are struck through in place and marked with the spec that closed them. ~~`architecture.md` §12 carries no open items and §13 states the constraints.~~ — **superseded 2026-09-01.** The rule is one-way by construction: §13 grew from 68 lines to 640 over seventeen specs with nothing pruning it, and unfinished work accreted there among the constraints while §12 read "None". **§12 is what is unfinished** — a defect nobody scheduled or a question left open, each entry naming what would close it — and **§13 is what the design will not do**, a limit it accepts and keeps accepting. A closed item is struck in place with the spec that closed it and its reasoning is *not* repeated in §13: that lives here in Key Decisions and in the delivery doc, and a third copy is a fork with no merge. (SPEC-021, revised 2026-09-01)


### A read-only finding is not closed until it has been run, and the job that runs it needs a floor rather than an exit code

**A read-only finding is not closed until it has been run, and the job that runs it needs a floor rather than an exit code** — fourteen sink modules reach a third party through one of eleven optional extras and none was ever executed, so the sinks most likely to be in production were the ones least verified. All three of SPEC-041's inherited "read-only" findings held up, and each was *reproduced before being fixed*: one `pg_terminate_backend` ended `PostgresSink` delivery for the process, a stock Logstash turned a batch of three into **one** event with every field as text in `message`, and NATS delivered **one of six** with every counter at zero. The guard on such a job is the repo's roster idiom, not `pytest`'s exit 5: exit 5 catches only a forgotten gate variable, while a fixture that skips on an absent service exits **0** — measured, a dropped module reads `13 passed` and a skip reads `15 passed, 1 skipped`. So an absent service **fails**, and a per-module floor makes a silent shrink loud. What stays unverified is a **derived** roster (`tests/test_sink_integration_roster.py`), and its population is the lazy-import modules ∪ those importing *or defining* `HTTPSink`/`SocketTransport`, because the obvious single-marker derivation silently omits `logstash` — the spec's own named minimum. **The job earned itself on its first run**, failing three tests no local run could: a service that has bound its port has not necessarily begun serving, so readiness is a real request, never a connect. (SPEC-041, arch §8)

### A rule with no gate is a rule that rots, and the cap that rots is the one contradicted by its neighbour

**A rule with no gate is a rule that rots, and the cap that rots is the one contradicted by its neighbour** — `CLAUDE.md` required "a description of **≤3 sentences**" and, in the sentence beside it, told authors that reasoning which would have been an inline comment belongs *in* the docstring. The code followed the second: measured at `451edf9`, 158 of 506 documented defs exceeded the cap reading "description" as the text before `Args:`, and 492 of 506 reading it as the whole docstring. Nothing checked any part of the rule, which is why nobody noticed for the ~30 specs it took to get there. The cap is therefore **re-scoped to the summary line** — one sentence, ending in a period, ≤100 characters, blank line after it — where the codebase already complied at **0 of 506**, so adoption cost no edit to `src/` and the gate shipped green. Deleting the cap outright was rejected: it is the line a reader meets in a hover or an index, and nothing else would have stopped a twelve-sentence one. Two neighbouring claims in the same bullet were also false and are fixed with it — the `Args:`/`Returns:`/`Raises:` trio is scoped to **functions and methods**, because 58 of 59 classes carry none of it and a class takes `Attributes:`; and the enumeration of test-asserted docstrings named three where there are seven, so it is replaced by the query that answers it. **The bullet says which of its clauses the gate actually enforces**, because the first draft of this change ended "`docstring-lint.py` gates all of this" and it does not: `Attributes:` is ungated and 37 of 59 classes carry none, so an unconditional wording there would have deleted a rule violated 158-of-506 and installed one violated 37-of-59, ungated, while claiming it was enforced. `python.md` §14's conditional form — public attributes, if any — is the one that matches the code. **The gate is `scripts/docstring-lint.py`, local like `docs-lint.sh` rather than a CI job**, and it owes a corpus for the same reason: running it over `src/` proves `src/` passes and says nothing about whether a check still fires. Its corpus caught a real defect on its first run — `ast.get_docstring(clean=True)` strips a leading blank line, so the empty-summary check could never fire against a cleaned docstring — and the mutation sweep covers every terminating condition **and every exemption and regex**, which is where false positives hide: dropping `SENTENCE_SPLIT`'s `\s+` turns 31 real summary lines into failures and no failing case can see it, and the naive `.`-count it replaces flags 39. Counts are deliberately not carried here; the corpus prints its own, and a number in a standing rule rots. Two traps are worth the space instead: the harness must run the checker from a **copy**, since it resolves its own root and would otherwise lint the real `src/` while every silence case passed vacuously; and it must assert the **interpreter floor**, because every fixture parses on 3.9 while `src/` does not, so a stale `python3` gives a green corpus over a gate that examined nothing. (SPEC-052)

**A gate's scoping test binds to what it scopes, or the word that fixes the defect is the word that hides it.** SPEC-053's check fails a sentence that names `_mark_inherited` and quantifies what the walk acts on with a bare universal, and its first design excused such a sentence whenever a scoping word — `reach`, `setdefault`, `residual` — appeared anywhere in it. That is the natural spelling and it is defeated by the vocabulary of the repair: inserting a scoping clause into the six known-bad sentences, without touching a claim, silenced **6 of 6**. It is not a hypothetical. `reclaim`'s docstring at `23fe6cc` said the walk had stamped everything inherited, and the sentence-wide form **missed it**, silenced by a `setdefault` fourteen words later in its own sentence — so the instrument this spec was written on had already been beaten by the defeat the spec was warning about. Bound instead to the **noun phrase the universal quantifies**, an insertion anywhere OUTSIDE the quantified noun phrase leaves the sentence firing, and one inside it silences the check by construction — which is what "bound to the noun phrase" means, not a leak in it. Two smaller rules came with it. A universal must be *about* the mechanism — requiring only that a universal and a name co-occur fires on "all of the buffer repair happens after it", and adding the about-the-claim clause took the live tree from 3 findings to 1. And a deliberate escape should be a **magic word**: `docs-lint: marking-walk` is explicit and greppable, so unlike `setdefault` nobody reaches it while paraphrasing, and it covers the one unit that carries it. (SPEC-053)

### The supported-Python versions have one authority — the CI matrix — and restatements are bound to it, not to each other

**The supported-Python versions have one authority — the CI matrix — and restatements are bound to it, not to each other** — `ci.yml`'s `python-version` matrix is the only one of the sites that is *evidence* rather than a claim: it is the set of runtimes a gate actually ran on. The sites it binds restate it — `pyproject.toml`'s classifiers, `requires-python` and `[tool.mypy] python_version`, the single pinned interpreter in `release.yml` / `integration.yml` / `pip-audit.yml`, four statements in `README.md`, CLAUDE.md's Tech Stack row, and both `docs/best-practices/` files — and until PR #200 nothing checked that they agreed. Measured, not assumed: the matrix was mutated to `["3.12", "3.13", "3.14"]` and all five gates exited 0. Both directions of drift were silent, and adding a version understates what the package supports while removing one leaves a classifier asserting a runtime nothing tests — the defect the hand-written classifier list exists to fix, since poetry-core otherwise derives classifiers from the `requires-python` *range* and a wheel built from `1040220^` — main immediately before PR #198 added the explicit list — really did ship `Programming Language :: Python :: 3.14`. **The claims are of two kinds and the distinction is load-bearing:** a *set* claim must equal the matrix, a *floor* claim its minimum, and a site carrying both is checked both ways — set equality alone passes "Python >= 3.13 … gates on 3.12 and 3.13", where every number present is right and the floor is wrong. Derived where derivable, per the SPEC-035/SPEC-040 roster rule: the workflow pins are found by globbing `.github/workflows/`, so a workflow added tomorrow is covered the day it lands. Prose has no schema, so those sites are anchored on the most *structural* thing on their line and **a missing anchor fails rather than skips**. Parsed with `re` — PyYAML is not in the dev group and the core is dependency-free, and `tomllib` would read three sites of the many. The two `docs/best-practices/` files are in because they are the two that had **already drifted**: `ae7447d` — one of whose four corrections was a `>= 3.13` floor stated **twice** in the rulebook CLAUDE.md routes every Python task through, and once more in the `INDEX.md` router row, which is the second file — and a stale floor there does not merely read wrong: it instructs the next session to write a call the floor cannot run. The rulebook states the floor twice *today* as well, in its scope blockquote and its Repo defaults bullet, and both are bound: binding one copy and not the other leaves the unbound one free to drift alone, which a repo-wide sweep for version tokens found and reading the file did not. **The fence is what the roster does NOT establish.** The matrix is an authority only while something consumes it and something triggers it; the first is checked, the second is not, and neither is "no `exclude:` thinned it" or "no `if:` skipped the job". Each is a fresh instance of one class — the authority can be neutralised upstream — so per the recurring-class rule the answer is written down rather than chased with a further check: the roster establishes that every *restatement it names* matches the matrix, **not that the matrix ran**. **The boundary is the LINE, not the file** — a restatement no anchor reaches is unbound even inside a file the roster reads, which is the shape of every gap found here: the rulebook's scope blockquote was bound while its Repo defaults bullet was not, then that bullet's floor was bound while its "CI gates 3.12 **and** 3.13" was not. Closing each by hand invited the next, so the mechanism changed instead: `check_version_lines_are_classified` sweeps the prose files and fails any line naming a *gated* version that no anchor reaches, unless it is classified as not a support claim — and **a floor anchor does not discharge a set claim**, because only a set check reads the whole line. Its population is gated versions rather than every dotted number, because outside an anchored line there is no context to tell `3.12` from `§3.1` or `timeout=5.0`: a first draft sweeping every token reported all three. Files outside `Sources` stay unbound and do exist — `src/log_foundry/decorator.py`'s flush-lock docstring says "the floor is `>=3.12`", `docs/architecture.md` says 3.13 "added `Queue.shutdown()` — which CI gates on", and the *comments* in `pyproject.toml` and the workflows explain the floor in prose the roster reads past. A **third** kind must not be aligned with the matrix at all: a claim about when a *language feature* appeared (`sanitize.py` on CPython 3.11+, the rulebook on `X | None` being 3.10+ syntax) is history, true whatever this package supports, and "fixing" it to agree would make it wrong. Nothing excludes those by shape — the gated-major filter does not, and an earlier draft of this entry wrongly said it did; what excludes them is anchoring, plus an explicit classification inside the swept files. Two review frames found the two defects that mattered, neither of which the other would have: building it found that nothing guarded the matrix being consumed, and walking the future edits found the gate green at the end of a floor-raise walk with three claims still false. Being a gate, it owes a fixture corpus asserting the failure *reason* with cases that assert silence — and a corpus mutant only counts if the guarded and unguarded code behave **differently** on it, which three of the first draft's did not. (No spec — PR #200)
