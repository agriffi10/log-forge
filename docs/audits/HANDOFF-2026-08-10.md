## What SPEC-034 shipped, and what a later spec must know

Four PRs (#136 signatures, #137 frozen config, #138 field namespace, #139 result and container
types). The delivery doc is `docs/spec-delivery/SPEC-034-public-api-freeze.md`; the four things
that change how you write the next spec:

- **`Health` and `SinkLosses` are frozen dataclasses.** Appending a field is a plain append —
  no index proof, no `len()` migration. This is what takes SPEC-036 FR-003 and SPEC-037 AC-5c
  off the critical path to 1.0.
- **`flush()`/`continue_trace()` return `FlushResult`/`ContinueResult`.** A new `reason` is
  additive by design. SPEC-036 owes two (`sink.flush()` failed, span sweep failed) and SPEC-036
  FR-001 AC-11a a third. `Worker.flush` carries the type too.
- **`config._live_config()` and `context._live_baggage()` are the internal reads.** Public
  accessors copy; the per-event path must not, and both are pinned structurally. If you add a
  per-event read, use the internal one.
- **`_config_lock` exists.** Order is `decorator._worker_lock` → `_config_lock`, never the
  reverse, and a test pins what may run under it.

## Method notes that cost time, and the harnesses that lied

**Seven of my own harnesses passed against the defect they were built to catch.** Each was
exposed only by mutating the code underneath it. This is the single highest-yield habit here:

| Harness | Why it was green against the bug |
|---|---|
| race harness for the config revert | barrier + 1 µs switch interval never entered the window; needed an *injected* one |
| 8-thread `_ensure_sink` test | the unlocked form still re-read the global on its fast path |
| emitter roster | searched for a literal `_log(...)` call, so a delegating emitter was invisible |
| echo assertion | `capsys` cannot see `ConsoleWriter`'s stream (bound at construction); `capfd` could not either |
| README `__all__` parser | an inline comment defeated `isidentifier()`, so the roster was empty |
| fixpoint test | the snippet listed the accessor first, where one pass already suffices |
| `h.sink is None or isinstance(...)` | short-circuits, so a missing import never fired |

Also:

- **A stale `.pyc` makes a mutation sweep lie in both directions.** A `cp` restore inside one
  second reuses the mutant bytecode. Always `PYTHONDONTWRITEBYTECODE=1`, or clear `__pycache__`
  between mutant and restore. If a test result contradicts the file you just read, check this
  first.
- **The venv has a `log_foundry.pth` pointing at the real `src`**, so a `git archive` copy is not
  isolated and `pytest --rootdir` does *not* override it. Use `PYTHONPATH=<copy>/src` and assert
  `log_foundry.__file__` is inside the copy.
- **Verify a scripted test rewrite by diffing `--collect-only` names, not pass counts.** The
  62-site conversion in Phase 4 was checked that way. Related: `str.replace(old, new, 1)` on a
  generic assertion string hits the *first* match, not the intended one — it put an assertion in
  the wrong test and asserted "thread-died" of an abandoned drain.
- **A mutant that substitutes a different *working* implementation proves nothing.** One of mine
  replaced `_rebind` with `object.__setattr__`, which also works; the real revert is the
  pre-fix code.
