## FR-005 — read this before building it

The spec's ACs were amended during Phase 1 and the amendments matter:

- **AC-0 settles on `after_in_child` only** — no `before`, no `after_in_parent`. The load-bearing
  argument is **not** cost: `before` does not run for a C-level fork (uWSGI calls
  `PyOS_AfterFork_Child` only), so every hazard it would close has to be closed in the child
  regardless, which makes a parent-side handler a partial fix bought at 1.20 s (90 s worst case
  with `HTTPSink`).
- **AC-0a's earlier "the file sinks are immune" claim was false and is struck in place.** The
  measurement behind it forked *after* `emit` returned, when the buffer is empty by construction
  — it exercised the non-hazard. A fork landing **inside** `emit`, between the write loop and the
  flush, duplicates the batch: reproduced three times, identical for `RotatingFileSink`. Any new
  fork measurement must be constructed to land in the window it claims to clear (interpose on the
  stream's `write`; do not hope the timing lands there).
- **AC-0b now requires the child to discard inherited buffered writes**, tested by forking
  mid-`emit`. AC-8 records what that cannot reach — a third-party client's buffer — in §13.
- **AC-2's lock roster must be derived**, and SPEC-036 FR-003 will add a lock after this spec
  ships that has to be picked up with no edit here.

FR-006 is the audit-C5 §13 entry: `_note_orphan_emit` and `_swap_sink` can write a `_diag` line
while holding `_worker_lock`, with `Worker.submit` named as the deliberate counter-example.

## Method notes that cost time this session

- **`git checkout --` destroys uncommitted work when restoring a mutant.** Copy to the scratchpad
  and restore from there. Verify a mutation actually applied — a `str.replace` matching nothing is
  a silent no-op that reads as a vacuous test.
- **Three of my tests failed on their own setup rather than on the defect**: an orphan `info()`
  emitting synchronously into a test gate; an expired-shutdown case that could not expire once
  FR-001 was fixed; and a latched `_shutdown_done` that declines a swap identically but leaves the
  drain thread alive, so nobody closes the old sink and the AC reads as a defect it is not.
- **CI caught a race my machine did not** — `sink.closed == 1` passed on 3.13 and failed on 3.12,
  because `_drain_finished` is set before the thread fully exits. The close is the wrong
  observable for "did the caller wait"; the drain flag plus an independent counter is right.
- **A lint's vocabulary must not come from the text it lints.** The first fused-word check seeded
  itself from the reasons, so every fused word validated itself.
