## The open question — merge, or close the accessor hole first

**Measured, on `7a10348`, reproduction below.** The roster identifies its subject by *name*
(`_SENTINELS = ("_worker", "worker", "draining", "retired")`, substring-matched). An accessor
whose own name contains none of them defeats it:

```python
def _snapshot() -> Worker | None:      # added next to _live_worker
    return _worker

# in _swap_sink, immediately before the out-of-lock branch:
    worker = _snapshot()
    if worker is not None:
```

Result: **roster 13 passed, full suite 1196 passed, 8 xfailed** — the exact baseline. The
out-of-lock guard is converted from liveness to existence with nothing red anywhere. The same
attack aimed at the **in-lock** branch *is* caught, but behaviourally, not by the roster
(`test_a_swap_after_a_retired_worker_hands_off_on_the_orphan_path`); the out-of-lock branch is
the one whose own roster row discloses that no shipped test distinguishes it, so there is no
second line of defence there.

The two options:

- **Merge as-is.** The exposure is disclosed at its widest in `_sites`' limitation 1 and in
  §9.2, and all four *historical* defects were mis-answered **existing** guards, which the
  stale-row check catches without exception. Ten rounds is well past diminishing returns.
- **Derive `_SENTINELS` from the module first** (~15 lines). Collect every module-level function
  whose body returns an expression naming the worker, and add those names to the sentinel set.
  `_snapshot` then names the worker and the site is filed. This also removes the last hand-list
  in a file whose whole argument is that hand-lists rot — `_SENTINELS` is currently four
  hand-written tokens. Expected to add **no** rows to the real module (every existing accessor
  name already contains `worker`), but that must be run, not assumed.

I lean to the second: it is small, it closes the class rather than an instance, and it is the
same move that finally worked on rounds 9→10. But it is a real decision and it was not mine to
take unilaterally at a context boundary.

## FR-005 — read this before building it

The spec's ACs were amended during Phase 1 and the amendments matter:

- **AC-0 settles on `after_in_child` only.** The load-bearing argument is **not** cost: `before`
  does not run for a C-level fork (uWSGI calls `PyOS_AfterFork_Child` only), so every hazard it
  would close has to be closed in the child regardless.
- **AC-0a's earlier "the file sinks are immune" claim was false and is struck in place.** Any new
  fork measurement must be constructed to land in the window it claims to clear (interpose on the
  stream's `write`; do not hope the timing lands there).
- **AC-0b requires the child to discard inherited buffered writes**, tested by forking mid-`emit`.
- **AC-2's lock roster must be derived**, and SPEC-036 FR-003 will add a lock after this spec
  ships that has to be picked up with no edit here.

### Measurements already taken — do not re-derive

All four were run on this machine (CPython 3.13.1); probes were in the session scratchpad, which
does **not** survive into a new session, so they are recorded here rather than referenced.

1. **CPython repairs its own `Thread` objects.** In the child, an inherited `Thread` reports
   `is_alive()` → `False` and `join(2.0)` returns in 0.000 s. So `_lifecycle`'s existing
   `is_alive()` filters self-prune and **no closer-registry reset is needed** — one piece of
   FR-005 that does not have to be built. State it rather than assume it.
2. **An inherited `Lock` stays locked with no owner** — `acquire(timeout=1)` → `False`. That is
   the audit's 19-of-60 hang, and re-initialising it is the library's own job.
3. **The child-side buffer discard works, and the unfixed case really does duplicate.** Forking
   with bytes pending in a `FileSink`-shaped buffered stream: without a discard the pending line
   appears **twice** on disk; with `os.dup2(devnull_fd, stream.fileno())` followed by reopening
   the path in append mode, it appears **once**, the child's own write lands, and the inherited
   object's eventual GC flush goes to `/dev/null` with no exception. That is the mechanism for
   AC-0b, and both directions are measured so the test will not be vacuous.
4. **`os.register_at_fork` child handlers run in registration order**, after `threading`'s own.

### Design settled (a draft of `_fork.py` was written and is lost with the scratchpad)

- **New `src/log_foundry/_fork.py`**, importing only `_diag` and `sinks.base`. It registers one
  `after_in_child` handler and exposes an **inverted registry** (`register_child_handler`) so it
  imports nothing that imports it. `decorator.py` — which owns `_worker` and the orphan records
  — registers the worker rebuild. Its worker questions then land in the FR-002 roster and must be
  classified, which is the roster working as intended.
- **Order in the child is the contract**: re-init locks → discard buffers → registered handlers.
- **AC-2's derived roster**: walk every `log_foundry.*` module in `sys.modules`, then descend
  only into log_foundry-owned instances/classes and plain containers (`MultiSink._sinks` is why
  containers are traversed). Third-party client state is deliberately out of reach and recorded
  in §13 — a boto3 session's locks are not ours to swap.
- **An identity memo is load-bearing, not tidiness.** A sink's `stop_signal` *is* the worker's
  `_stop`; replacing them with two different events would leave the worker setting one and the
  sink waiting on the other. The memo is also what makes it safe to re-init `threading.Event`s
  at all, and they carry their set state across.
- **Rebuild the worker in place** (`Worker._reinit_after_fork`), not as a new object, so
  ownership guards keyed on `_worker.sink is X` and `_lifecycle`'s registry stay valid. Fresh
  queue (AC-5), same sink (AC-3), counters zeroed, and a **retired parent stays retired** — a
  fork does not undo a `shutdown()`.
- **AC-0b hook** probed by name (`discard_buffered_after_fork`), documented next to
  `read_losses` in `sinks/base.py`, the same optional-protocol shape as `losses()`.
- **AC-2 completeness proof**: an AST test that every `threading.Lock()/RLock()/Event()`
  construction in `src/` is assigned to a module global or a `self.<attr>` — shapes the traversal
  reaches. A lock held inside a container would be unreachable, so the test forbids it. This is
  what picks up SPEC-036 FR-003's lock with no edit.
- **AC-8/§13 has an occupant I did not expect**: `StdoutSink` writes to `sys.stdout`, a
  **process**-owned buffer, so it carries the same fork duplication hazard as the file sinks —
  but the library must not discard the application's pending output. Record it, do not fix it.

## Method notes that cost time this session

- **Parallel reviewers share the working tree, not just the scratchpad.** A reviewer had
  `decorator.py` mutated while I ran the suite, and two roster tests failed for reasons that were
  not mine. The existing memory covers scratchpad collisions; this is worse. Serialize reviewers
  that mutate `src/`, or give each one a git worktree.
- **A killed subagent leaves its mutation in your tree.** Round 11 was stopped mid-attack and
  `decorator.py` was still carrying `_snapshot()`. Check `git status` after any interrupted
  agent, and read the diff before restoring — in this case the leftover *was* the finding.
- **`git checkout --` destroys uncommitted work when restoring a mutant.** Copy to the scratchpad
  and restore from there. Verify a mutation actually applied — a `str.replace` matching nothing
  is a silent no-op that reads as a vacuous test. This bit again: two mutations this session
  reported "no-op" and had to be re-anchored with exact indentation.
- **Mutation-test every fix before pushing it.** Round 8 found that round 7's headline change
  could be reverted with the suite green. Every commit since has ended with a mutation sweep, and
  round 9's and round 10's fixes were both verified against the exact attack that motivated them.
- **A lint's vocabulary must not come from the text it lints**, and its *scope* must not either.
  Round 8's finding was the scope gate naming its own targets.
