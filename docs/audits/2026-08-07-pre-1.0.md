# Pre-1.0 Audit — 2026-08-07

Run while preparing the `v1.0.0` tag, across four surfaces in parallel: the public API, silent
data loss, concurrency, and the sink family. It is the second audit of this project; the
2026-08-05 one produced SPEC-024..033.

**Outcome: the tag is held.** Several findings contradict promises the README and the shipped
specs actively make, and the API items freeze permanently once `1.0.0` ships.

Every finding below was **reproduced by running it**, not inferred. Where a finding is
read-only analysis it says so. Line references are against `734a9b2`.

---

## The three that decided it

### A1. `flush()` is blind to an open span — and the documented Lambda recipe calls it there

An in-span event is appended to `span.events` (`api.py:78-80`) and nothing reaches the worker
until the span closes (`decorator.py:788-790`). `Worker.flush` drains the *queue*
(`worker.py:414-477`). So `flush()` inside a `@trace`d function has, by construction, nothing to
drain. `README.md:930-949` — the headline serverless recipe — does exactly this.

```
README guard: drained=True  failed_batches=0 dropped=0 queued=0 stopped_reason=None
delivered so far: []
after the handler returns, delivered = []
```

Zero events delivered, every surface clean, nothing on stderr. `queued` reads `0` even after the
handler returns, because the drain thread has already taken the submission into its private
`pending`. In a reaped container — which `README.md:908` correctly says `atexit` will not save —
they are gone. Generalises beyond Lambda: any long-lived `@trace`d span (a consumer loop, a
server `main`) buffers indefinitely with every surface reading clean.

### A2. `@trace` fails the caller where the orphan path does not

`api._log` guards only the orphan branch, on the stated grounds that the in-span branch "only
appends to a list" — but it calls `build_event` → `truncate_str` → `value.encode`
(`model.py:99`, `sanitize.py:98`).

```
lf.info(some_exception)   orphan path → returned normally
                          in-span     → CALLER GOT AttributeError: 'ValueError' object has no attribute 'encode'
```

Identical call, opposite outcomes. Inside a span the library kills the caller's function — the
failure SPEC-025 exists to eliminate — and the decorator's handler then records the span with
`status=error` and an `error.type` the user's code never raised. Wrong data *and* a broken
caller. `info(exc)` is an ordinary slip that `mypy` catches only at typed call sites.

### A3. `get_config()` is a public back door around the SPEC-030 sink swap

`get_config()` returns the live mutable singleton.

```
configure(sink=A) → work() → get_config().sink = B → work()
  A got 4    B got 0    config claims B    incomplete_swaps=0    A never closed
  get_config().max_value_bytes = 0   accepted (configure() rejects it)
```

That is the defect SPEC-030 was written to fix, reachable with no underscore in sight, plus a
bypass of `_require_positive`. Freezing "the config object is yours to mutate" makes the swap
machinery advisory for all of `1.x`.

| # | Finding | Evidence |
|---|---|---|
| L1 | **`flush()` blind to an open span** | A1 above |
| L2 | **`os.fork()` — the worker thread does not survive and nothing says so.** No `os.register_at_fork` anywhere. | L2b | **Fork while the drain thread holds a SPEC-028 sink lock → the child hangs forever** on its first orphan `info()`, on the application's own thread. | child exited on SIGALRM (status 14); only the test's alarm ended it. | L3 | **`flush()` cannot reach a client-buffering sink.** `KafkaSink.emit` hands to librdkafka; `producer.flush()` runs only in `close()`. `GooglePubSubSink` resolves futures only in `close()`. `Sink` declares no flush hook. | stand-in with that shape: `flush() → True`, on the wire 0, in the client buffer 3, `health()` all zeros. | L4 | **An `asyncio` task appends to a span buffer already emitted.** `contextvars` copies the same `Span` object into every task; `submit` hands the live list to the queue and never detaches it. | Same code twice: under the worker's 1 s interval the event is delivered but ordered *after* `span.end`; over it, silently lost. |
| L5 | **A permanently dead `MultiSink` child never appears in `health()`.** `emit` isolates a failing child unless *all* fail; `losses()` sums only children implementing it. | one of two destinations delivered nothing, ever: `flush() → True`, `health()` all zeros. |
| L6 | **The orphan path's own loss is invisible.** Already specced as SPEC-034 FR-004. | `health()` all zeros over five lost events. |

## Sink correctness

| # | Finding | Status |
|---|---|---|
| K1 | **The exit drain hands one huge batch to sinks that never re-chunk.** `_final_drain` emits everything pending as a single batch; the HTTP family is the only one that does not re-chunk (every queue/stream sink uses `chunk_items`). Datadog caps at 1,000 entries / 5 MB, New Relic 1 MB, Honeycomb 5 MB. The resulting 400/413 is not in `_send`'s retryable set (429/5xx only), so the whole exit backlog is abandoned in one request. | reproduced: **5,980 events in one `emit`** once the queue backs up |
| K2 | **`PostgresSink`: a failing `rollback()` bypasses the retry loop, the loss counter and the diagnostic.** `self._conn.rollback()` is unguarded inside the `except` (`postgres.py:157`); psycopg raises from it when the server closed the session — the most common reason the insert failed. | reproduced: attempts 4 → 1, `failed=0` after total loss, no `_diag.lost`, raw driver exception reaches the worker instead of `SinkDeliveryError` |
| K3 | **`PostgresSink` never resets a broken connection.** Opened once in `__init__`, never reopened; retries run against the same dead handle. One failover ends delivery for the process lifetime. Every sibling recovers. | read-only |
| K4 | **`GooglePubSubSink` retains every publish future until `close()`.** Append-only for the process lifetime: unbounded growth, and `failed` stays 0 through an entire outage. | read-only |
| K5 | **`FirehoseSink` writes records with no newline delimiter.** S3 objects come out `{"a":1}{"b":2}` — unparseable by Athena/Glue/OpenSearch ingest, and inconsistent with the NDJSON every other sink emits. | read-only |
| K6 | **`KafkaSink.close()` flushes with no timeout and discards the return.** `Worker.shutdown` closes the live sink inline and unbounded, so an unreachable broker holds process exit for `message.timeout.ms` (5 min default) despite `shutdown(timeout=30)`. `flush()` returns the count still queued — the exact loss at exit — and it is thrown away. | read-only |
| K7 | **`SyslogSink` retries an oversized UDP datagram instead of dropping it.** EMSGSIZE is permanent; every other size-limited sink drops-and-counts before sending. | reproduced: ~16 futile sends and seconds of backoff on the one drain thread, never converging |
| K8 | **Redis stream and list sinks grow without bound at the destination.** No `maxlen`/`ltrim` and no option to set one. As the durable buffer arch §9.1 recommends, a stalled consumer OOMs Redis. | read-only |
| K9 | **Kinesis/Firehose byte budgets are wrong at the margins.** Firehose's per-record limit is 1,000 KiB, not `1024*1024`; both size requests ignoring the up-to-256-byte `PartitionKey` per record, while `SQSSink` deliberately charges its FIFO ids and documents why. | read-only |
| K10 | **`LogstashSink` HTTP mode sends `application/x-ndjson`**, which Logstash's `http` input maps to the `plain` codec by default — the whole body arrives as one event. | read-only, lower confidence |

## Public API — freezes at 1.0

| # | Finding |
|---|---|
| P1 | **`get_config()` returns the live singleton** (A3 above). |
| P2 | **`echo` and `message` are reserved words stolen from `**fields`.** `info("x", echo=...)` silently drops the field *and* switches on console output; `message=` raises `TypeError`. No escape hatch. |
| P3 | **`Sink` is not exported** — the extension point the README documents over 40 lines. Nor are `Config` (the return type of a public function), `read_losses`, or `get_baggage`; baggage is publicly settable but readable only as a serialized header the caller must re-parse. |
| P4 | **`stop_signal` is an undeclared, un-namespaced attribute** the library assigns onto third-party sink objects. `sinks/base.py` — designated as the third-party contract — never mentions it. A sink owning that attribute name has it clobbered. |
| P5 | **`flush() -> bool`** is one bit for five outcomes (timed out / retired / thread died / queue full / batch abandoned). `continue_trace() -> bool` has the same shape. A NamedTuple cannot be retrofitted — a non-empty tuple is always truthy. |
| P6 | **`Health` and `SinkLosses` are `NamedTuple`s**, so unpacking and `len()` are part of the frozen contract. `Health` has grown in six consecutive specs; `d, f = sink.losses()` breaks the moment `SinkLosses` gains a third counter. |
| P7 | **No public way to redirect or disable the console echo.** `ConsoleWriter` is not exported and `configure()` has no `echo` argument; the only route is assigning `log_foundry.api._console`. |
| P8 | **The worker is unconfigurable** — `batch_size`, `flush_interval`, `max_queue`, `max_retries` are unreachable from `configure()`, so a user watching `health().dropped` climb has no remedy but to log less. `DEFAULT_SWAP_TIMEOUT` is not exported while `DEFAULT_SHUTDOWN_TIMEOUT` is. |
| P9 | **Naming and positional-argument policy are inconsistent for the same concept.** The routing key is `key_field` / `partition_key_field` / `message_group_id` across three sinks, and only SQS accepts a callable. The destination name is positional for `PostgresSink(table)` and keyword-required for `ElasticsearchSink(*, index)`. `MemorySink`/`NullSink`/`StderrSink` live in `sinks.util`. Seven sinks take `**http_kwargs: object`, which type-checks nothing. |

## What is *not* broken

Checked and found sound, so a later reader does not re-audit them: `sinks/_batch.py` positional
adjudication, `sinks/_retry.py` clamping, `sinks/_chunk.py`, the worker's queue-full / retry /
terminal-failure / flush-marker-release paths, `swap_sink`'s two-drain fence, `_lifecycle`'s
closer grace, the `dropped`/`failed`/`dropped_oversized`/`dropped_unadjudicated` instrumentation
across the transport sinks, `SQSSink`'s chunking and id-keyed adjudication, `SQLiteSink` and
`FileSink` locking, `MultiSink`'s total-vs-partial rule, `AzureEventHubsSink` packing, no fd leak
on `HTTPSink`'s error path, and tz-aware timestamps throughout.
